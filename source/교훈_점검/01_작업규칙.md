# 작업 규칙 — 사용자가 정한 것

## 말하기
- 한글로, 결론부터, 짧고 쉬운 말로. 호칭("형님" 등)은 쓰지 않는다.
- [L075] 작업 시간·난이도를 낙관적으로 말하지 않는다. 예상은 "판 몇 번"으로 말하고 틀리면 바로 알린다.
- 막힌 것·못 하는 것·이상한 것은 발견한 즉시 알린다. 물어볼 때까지 들고 있지 않는다.
- "진행 몇 퍼"라고 물으면 진행률만 답하고 작업은 멈추지 않는다.
- 더 쉬운 방법이 있으면 지시대로만 하지 말고 먼저 말한다.

## 만들기
- 파일·패치는 사용자가 "만들어"라고 할 때만 만든다. 그 전에는 계획만 말한다.
- [L122] 단, 이 `교훈_점검` 폴더는 예외다. 정한 방침·순서·규칙, 받은 제보, 찾은 실수는 "만들어"와 상관없이 그 자리에서 적는다(사용자 11-10: 이 폴더는 전부 들어가 있어야 하는 필터).
- 계획·예시를 내기 전에 관련 코드부터 전부 읽는다. 경우의 수를 처음부터 다 따진다.
- 게임 실행 파일·원본 데이터·세이브는 디스크에서 고치지 않는다.
- 실시간으로 계속 읽어서 렉이 생기는 방식은 쓰지 않는다. 그 방법밖에 없으면 먼저 말한다.
- 모드(맵 확장·AI·2D·계절·기색·통합패치)는 설치 순서와 상관없이 각자 돌아야 한다. 서로 종속되거나 파일 자리를 빼앗지 않는다.
- 남이 만든 모드와의 충돌은 통합패치 쪽에서 맞추지 않는다.
- [L017] 손으로 파야 하는 이식은 하지 않고 그 기능을 우리 소스로 새로 짠다. 소스 있는 모듈은 처음부터 다시 빌드한다.
- 통합패치의 모든 모듈을 원소스가 있는 상태로 만든다(2026-11-10). "원소스가 없어서 못 했다"가 나오면 안 된다.
- 옛 판에 없던 기능(진단 기록 등)을 임의로 덧붙이지 않는다. 사용자가 승인한 것만.
- 수정 확인용 시험 버튼은 본판에 넣지 않는다. 별도 시험 파일에만.
- 프레임·렉 측정은 끼어드는 자리마다 달아 두되 평소엔 끈다. 사용자가 프레임 개선하자고 할 때만 켠다.

## 문제·제보
- 문제가 생기면 오류창을 자세히 띄운다. 조용히 꺼지지 않는다.
- 다른 모드와 충돌이면 창에 크게 "다른 모드와 충돌"과 그 모드(DLL) 이름.
- 꺼 둔 기능·안 깐 번호는 오류창을 띄우지 않는다.
- 남은 옛 파일 때문에 뜨는 오류창은 창을 숨기지 말고 옛 파일을 없앤다.
- 우리 모드를 넣은 뒤 생긴 문제는 다른 패치 탓으로 돌리지 않는다.
- 제보자에게 파일을 요청하지 않는다. 제보자는 오류창 글자만 댓글로 적으면 되게 한다.
- 사용자에게 상황을 만들어 시험하게 하거나 "평소처럼 게임하면 기록 읽겠다"고 떠넘기지 않는다. PC 를 직접 조작하는 긴 시험도 하지 않는다.
- 측정판·진단판을 넣어 보겠다는 말을 반복하지 않는다. 옛 판과 대조해 스스로 찾는다.
- 한 번이라도 말한 문제는 새 판마다 다시 확인한다(제보 장부).
- 한 방법이 틀렸으면 다른 방법으로라도 결과를 낸다. "알려진 제한"으로 남기지 않는다.

## 시험·넘기기
- 새 판은 전체 시험을 다 돌린 뒤에 넘긴다. 바뀐 부분만 확인하고 먼저 넘기지 않는다. (= 관문)
- 게임 메모리 스냅샷을 떠서 에뮬에 올리는 무거운 검증은 하지 않는다.
- 화면에 보이는 것은 그리기 명령을 가로채 그림으로 확인한다. 바뀐 기능마다 자가진단 기록을 남긴다.
- 게임 폴더 튕김 기록(`SAN14_기록\튕김_*.log`)을 매번 확인하고, 새 튕김은 어느 DLL·함수인지까지 짚는다.
- 확인된 수정은 모아서 한 번에 넣는다(게임 껐다 켜는 횟수 줄이기).
- [L126] 본판을 완성할 때는 확인용 측정·결과 기록(달 기록 world·census·orders, invest_skip, counts_rewritten, 성능 측정 등)을 전부 빼거나 꺼서 프레임 하락이 없게 한다(사용자 11-10). 확인이 끝난 기록부터 뺀다. 남기는 것은 오류창과 실패 기록뿐.
- [L132] (사용자 11-11) 정식 폴더에 넣는 판 = 본판. 본판에는 처음부터 확인용 기록을 넣지 않는다. 확인용 기록은 하나의 스위치로 묶어 시험판에서만 켜고, 관문이 본판에서 켜져 있으면 막게 한다(다음 판에서 만듦).
- 시험 도구 끝에 숫자로 답하게 하는 질문을 넣지 않는다. 결과 txt 를 따로 만들지 않는다(게임 폴더 기록을 직접 읽는다).
- 자료 수집은 한 번 실행으로 몽땅.

## 파일 두는 곳
- 덮어쓰기 파일은 PC 정식 폴더에 직접 덮어쓴다(위치는 `06_기준값.md`). 관문을 통과한 판만.
- 검증 전 판은 정식 폴더에 넣지 않는다. 따로 둔 시험 폴더에.
- 통합패치 전체 압축본은 만들지 않는다(덮어쓰기 파일만). PC 폴더에 넣은 파일은 채팅에 따로 올리지 않는다.
- (사용자 11-11) 예외: 깃허브 저장소 updates 폴더에 기본판 전체 조각(90MB 미만, 한 번만)과 판마다 바뀐 파일 ZIP·판 목록을 올린다(저장소 wprkfdid12-ux/san14ce-integrated-patch, 올리기는 Claude 가 git push). 이 작업 환경은 깃허브 '배포' 칸 올리기가 막혀 있음(HTTP 403). 새 설치기 판은 PC 에서 한 번 켜 본 뒤에 판 목록(index.json)을 올린다.
- 소스는 고칠 때마다 결과물 폴더와 PC 소스 폴더 두 곳(`작업재료_R31_20261019`, `업데이트대비\1_소스`)에 넣는다. 이 `교훈_점검` 폴더도 같이.
- 보내는 ZIP 은 분할 형식(…_1of1.zip). 작업 보관본은 요청 전에는 보내지 않는다.
- 설치기·실행기는 게임 폴더 안에 두지 않는다.
- PC 작업은 승인 창이 덜 뜨게 한 번에 묶어 보낸다. 되도록 덮어쓰기.

## 다른 사람 모드 호환판(AI 모드 등)
- 고치는 것은 전부 그 모드 쪽. 통합패치·계절·2D·기색은 손대지 않는다.
- 겹치는 기능은 항목에 "통합패치 N번과 겹침"을 표시하고 체크칸을 잠근다(회색). 원작자 표시(주황)는 건드리지 않는다.
- 기능을 빼지 않고 안쪽을 고쳐 원래 기능이 돌게 한다. 개발용 탭은 그대로 둔다.
- 남의 저장소 코드는 실행하지 않는다(글자만 읽고 우리 도구로 뽑음). 통합편의 확인 구간 안 자리는 끄지 말고 "통합편의 확인 뒤에 걸기"로. 딸린 항목도 같이 잠금(L140·L141).
