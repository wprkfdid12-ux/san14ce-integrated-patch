# 점검표 6 — 설치기(installer101)를 고치거나 꾸러미 구성을 바꿀 때

- [L040] 게임 안에서 값이 바뀌는 ini(설정 창이 써 넣는 것)는 RuntimeIni 목록에 있는가. 없으면 "다른 프로그램이 바꾼 파일"로 설치가 멈춘다.
- 모듈 DLL 을 더했으면: manifest 줄, 등록 ini([Mod] File=·Enabled=1·CoreABI=65536), 종합 진단 feature_table, 설치기 게임 적용 판정 문구.
- 모듈을 뺐거나 이름을 바꿨으면: RetiredTargets 에 옛 파일. 옛 이름의 사용자 설정을 이어받는가.
- [L045] 20·31번 말고 아무 번호나 고르면 1번이 같이 깔린다(18·24 포함). 번호를 더하면 이 규칙에 넣을지 정한다.
- [L042] 설치 기록이 깨졌거나 연결 폴더·없어진 백업이 있어도 멈추지 않고 진짜 이유를 보여 주는가.
- [L047] 설치기·실행기는 게임 폴더 밖(바탕화면 쪽)에서 돈다. ZIP 을 따로 풀었거나 쓰기 제한 폴더·백신 차단이어도 이유를 글자로.
- 안 고른 항목의 남은 파일 정리 규칙: 우리 Id 목록의 등록 파일·알려진 해시의 파일만. 남의 모드·공용 런타임·게임 자료는 그대로. 사본은 `.san14ce_compat_r3/leftover/`.
- C# 컴파일러가 여기 없다 → `test/test_installer_syntax.py`·`test_installer_leftover.py` 를 꼭 돌린다. 실제 컴파일은 사용자 PC 의 `설치.cmd`(csc /warnaserror+).
- 번호·이름을 바꾸면 README·설정 창 설명·진단 문구의 번호도 같이.
- [L144] 설치기 소스를 고쳤으면 `test/test_installer_update.py`(C# 5 문법·깃허브 새 판 받기 짝)를 돌리고, PC 에서 설치.cmd 를 한 번 켜 컴파일되는지 본 뒤에 깃허브 판 목록(updates/index.json)을 올린다(그 전엔 판 ZIP·조각만). 새 판 파일은 `make_release_r43.py <판>`(관문 도장 필요, 설명글 release/<판>_설명.txt). 판 번호(Spec.Version)를 올리면 깃허브 태그도 같은 글자.
