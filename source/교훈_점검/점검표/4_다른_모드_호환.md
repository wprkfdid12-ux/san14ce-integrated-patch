# 점검표 4 — 다른 모드와 같이 쓰게 할 때

## 원칙
- [L082] 남이 만든 모드와의 충돌은 통합패치 쪽에서 맞추지 않는다. 통합패치·계절·2D·기색은 손대지 않는다. 사용자가 개인용 호환판을 시키면 **그 모드 쪽만** 고친다.
- [L082] 기능을 빼서 맞추지 않는다. 안쪽을 고쳐 원래 의도한 기능이 돌게 한다. 뺄 수밖에 없으면 먼저 말하고 사용자가 정한다(예: 이동 속도 맞추기 49곳은 사용자 결정으로 뺌).
- [L083] 다른 모더가 통합패치에 맞춰 둔 자리(파일 이름·설정·호환 자리)는 바꾸지 않는다.
- [L081] 공용 이름 파일에 기대지 않는다. 우리 것은 우리 전용 이름(예: SAN14_Resolver_IP01.dll).
- 맵 확장·AI·2D·계절·통합패치는 설치 순서와 상관없이 각자 돌아야 한다.

## 대조하는 법
1. 우리 자리: `자료/우리자리.tsv`(게임 기록에서 뽑음 — 반드시 `도구/자리표_만들기.py` 로) + 통합편의 표(전역 확인·포인터·후크·6번 준비) + 14번 152칸 + 9번 146칸·5자리.
2. 그 모드의 자리(주소표·소스·바이너리)와 같은 판 주소끼리 대조한다. 판이 섞인 표로 대조하지 않는다.
3. 결과를 셋으로 나눈다: 같은 자리(충돌) / 기능만 같음(겹침) / 확인 못 함. 확인 못 한 것은 그렇게 적는다.
4. 겹침 = 그 모드 쪽 항목을 끄고 "통합패치 N번과 겹침"을 잘 보이게 표시 + 체크칸 잠금(회색). 충돌 = 그 모드 쪽에서 피하게 고친다. 통합편의 확인 구간 안의 자리는 통합편의 확인이 끝난 뒤(`SAN14_WaitConvenienceV1`) 걸게 하면 둘 다 돈다.

## 남의 파일을 고칠 때
- [L080] 남의 DLL 의 PE 구조(구역 추가 등)는 바꾸지 않는 게 기본. 꼭 구역을 더해야 하면 실제 파일을 올려 돌리는 흉내 시험을 만든 뒤에만(구역 머리·정렬·이미지 크기·재배치 없음 확인).
- [L085] 남의 설치 관리자(.NET exe)를 고치면 전 메서드 검증(ai_compat/v159/il_check.py 방식)으로 토큰·분기 대상을 확인한다.
- 원작자가 쓰는 표시(예: 바뀐 항목 주황색)는 건드리지 않고, 우리 표시는 구별되게(회색).
- 개발용 탭 같은 것은 사용자가 그대로 두라고 하면 둔다.
