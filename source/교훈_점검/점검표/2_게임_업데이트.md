# 점검표 2 — 게임 공식 업데이트가 나왔을 때

소스 자립이 끝나면 이 일은 "소스의 주소 표를 새 판 값으로 바꾸고 다시 빌드"로 줄어든다. 아래 이식 교훈은 소스 없는 바이너리가 남아 있는 동안만 필요하다. 그래서 바이너리를 옮기는 데 시간이 길어지면 옮기지 말고 그 모듈을 소스로 새로 짠다. [L017]

## 0. 시작 전
- 게임 폴더는 모드가 깔린 그대로 둔다. 무결성 검사·재설치는 하지 않는다. 업데이트 전 원본 exe 는 따로 보관.
- [L015] 새 exe 의 해제본(암호 풀린 이미지)부터 만든다. 디스크의 exe 는 암호화돼 있어 그대로는 못 읽는다.
- 새 판 기준값(빌드 시각·이미지 크기)을 `06_기준값.md` 와 `src/version.h` 에 적는다(c05 가 둘을 맞춰 본다).
- [L019] 게임 구조 값(데이터 루트, 무장 표, 고용 풀, 지역 표, 세력 표, 클래스 vtable, 월 처리 실행기 등)을 새 판에서 다시 찾아 `06_기준값.md` 에 적는다.
- [L016] 데이터 파일이 바뀌었는지 본다: fixdataexce.s14(설치기 기대 헤더), ScreenLayout·CharacterEditor·KIDSSystemResource·RRPreview 색인(10·20·31번 자료와 원본 사본).
- 순서는 "새 판 분석 보고(1단계) → 호환 작업(2단계)". 예상은 판 몇 번으로 말한다.

## 1. 소스 모듈
- 주소는 연결자리 대장(upd_tools/ledger.tsv)에서 새 판 값으로. 새로 만든 모듈의 주소도 대장에 들어 있어야 한다.
- 전부 다시 빌드 → 관문.

## 2. 바이너리 모듈을 옮길 때(남아 있는 동안)
자동 도구(upd_tools/apply_new.py 등)가 놓치거나 틀리는 꼴. 하나씩 전용 점검 도구로 전수 조사한다.
- [L001] 주소가 아닌 상수를 주소로 바꾸지 않았나(imm_audit_r43.py). 0xffffff·0x7fffff·π 가수·0x10ffff 같은 값.
- [L002] `lea [레지스터+숫자]` 꼴의 진짜 주소를 놓치지 않았나.
- [L003] 4자리 주소를 놓치지 않았나.
- [L004] 두 함수 사이 차이값(델타)을 옮겼나(delta_sel_r43.py).
- [L005] 짧은 함수·쌍둥이 함수를 닮은 함수로 옮기지 않았나 → 옛 호출처에서 새 함수 다수결, vtable 대응.
- [L006] 코드 주소가 아니라 자료 구조 안 오프셋인 숫자를 건드리지 않았나.
- [L007] 코드 즉시값 말고도: 리졸버 지문 표(형식 3가지), 자료 구역의 기대 바이트·RVA 기록, 절대 포인터, 마스크 패턴. 첫 실행 전에 모듈별 시작 검사 흉내(ic_verify_r43.py)를 돌린다.
- [L008] 자리 대응표에 모듈 자기 주소가 섞이지 않았나. 모듈 이미지 범위 안 값은 번역하지 않는다(base_flow_r43.py, test_ic_self_refs.py).
- [L009] 스택·레지스터 즉시값 기록 / `or reg,주소|k` / 8바이트 미만 기대 조각 / 계산된 base 뒤 변위 / 같은 숫자가 옛·새 양쪽 주소(전역 치환 금지, same_value_r43.py).
- [L010] 음수로 적힌 주소 상수(neg_imm_r43.py), 2단 포인터 검사표 양쪽(ptr_pairs_r43.py), {종류,칸,대상} 표의 대상 열.
- [L011] switch 이분탐색 경계값(split_cmp).
- [L012] base 를 바꾼 뒤 쓰는 상대 주소 상수(rel_base_r43.py).
- [L013] 후크 되돌아가기 자리를 바꿨으면 건너뛴 명령이 없는지 한 줄씩.
- [L114] 모듈 안 글자열(셰이더 진입점 이름 등)이 주소로 오인돼 깨지지 않았나 — 글자열 전수 검사.
- 판정 뒤: 모든 call/jmp 대상이 새 판의 함수 시작인지, 시작 기록 문구가 옛 판과 같은지 대조.

## 3. 옮긴 뒤 반드시
- 지문(해시)을 확인하는 모듈 전부 갱신(점검표 1).
- 모든 모듈의 시작 기록을 전수 확인. 조용히 꺼진 것이 없어야 한다.
- 제보 장부의 옛 제보를 회귀 항목으로 다시 본다(튕김: 개성 마우스오버, 출진, 편집 화면, 일기토, 턴 진행).
- 성능 패턴(매 프레임 다시 칠하기 등)이 다시 생기지 않았는지.
- 새 판 표식(자리표_만들기.py 의 NEW_MARK)을 새 판에만 있는 이름으로 바꾼다 — 게임 기록 머리줄의 판 글자는 믿지 않는다.
