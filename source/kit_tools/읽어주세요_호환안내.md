# 삼국지14 CE 통합패치 R43 — 다른 모드 호환용 자료

이 묶음은 통합패치 R43과 같이 돌아가는 모드를 만들려는 분을 위한 자료입니다. 이 자료는 게임 빌드 `0x6ad06f53`, 곧 1.0.1 다음 공식 판(실행 파일 크기 `0x2a02000`) 기준입니다.
주소는 전부 **게임 실행 파일 기준 RVA**입니다(게임 시작 주소 + RVA = 실제 주소).

## 2. 제일 흔한 충돌: 통합편의 확인 구간

통합편의는 게임이 켜지고 약 1초 뒤, **한 번만** 표 02·03·04의 자리가 원래 모양인지 확인합니다.
하나라도 다르면 그 구간에 기대는 기능(예: 5번 수행·대열 이동)을 **설치하지 않습니다**.
통합패치에는 시작 종합 진단이 있어서, 이럴 때 "통합편의 기록에 실패 줄" 오류 창이 뜹니다(진단 코드 R43D-2).

다른 모드가 이 구간 안을 고쳐야 한다면, **통합편의가 확인을 끝낸 뒤에** 고치면 둘 다 동작합니다.

```c
// 통합편의 확인이 끝날 때까지 기다린 뒤 고치기 (별도 스레드에서)
HMODULE ic = GetModuleHandleW(L"SAN14_IntegratedConvenience.dll");   // 아직 안 실렸으면 잠깐씩 다시 확인(최대 1~2분)
if (ic) {
    typedef unsigned (*WaitFn)(void);
    WaitFn wait = (WaitFn)GetProcAddress(ic, "SAN14_WaitConvenienceV1");
    // wait(): 확인이 끝났으면 1. 아니면 최대 15초 기다리다 0. 0이면 다시 부르면 됨(우리는 최대 10분까지)
    if (wait) while (!wait()) { /* 시간 제한 두고 반복 */ }
}
// 여기서 패치
```

- 게임 폴더에 `SAN14_IntegratedConvenience.dll` 파일이 없으면 기다리지 말고 바로 고치면 됩니다. 그러면 통합패치에 기대는 구조가 되지 않습니다.
- `DllMain` 안에서 `wait()`를 부르지 마세요(로더 잠금). 스레드를 하나 만들어 그 안에서 부르면 됩니다.
- 통합패치 쪽 예: `소스/src/ic_after_restore.h` (우리 29번·32번 모듈이 이 방식).

## 3. 누가 어느 자리를 가졌는지 보기

- `%LOCALAPPDATA%\SAN14CE_ModCore\runtime.log` : ModCore를 거쳐 패치하는 모듈은 `이름 RVA=xxxxxxxx len=N` 줄을 남깁니다(표 01은 이 기록에서 뽑았음).
- `게임 폴더\SAN14CE_11Patch.log` (UTF-16) : 통합편의가 기능마다 설치/실패를 남깁니다.
- `게임 폴더\SAN14_기록\적용확인.log` : 통합패치 각 모듈의 시작 결과와 종합 진단(R43D 줄).
- 통합패치 모듈은 고치려던 자리가 이미 바뀌어 있으면 **조용히 꺼지지 않고** 오류 창을 띄웁니다.
  - 창에는 어느 자리를 누가(어느 DLL) 가져갔는지 적힙니다(`소스/src/r43_conflict.h`).
  - 다른 모드가 가져간 경우 "다른 모드와 충돌"로 크게 표시됩니다.

## 4. 소스와 빌드

- `소스/build_all.sh` : 통합패치 우리 모듈 24개 빌드(clang + lld, 윈도 SDK 필요 없음, 리눅스·WSL에서 확인).
- `소스/mt/build_new.sh` : 13번 MeritTraits와 그 리졸버.
- **이 소스로 다시 빌드하면 배포판 DLL과 바이트까지 같은 파일이 나옵니다(28개).** 목록은 `모듈목록_소스여부.tsv`의 "소스 있음".
- `소스/kits/WheelRegion`, `소스/kits/DragLearn` : 30번 휠클릭 지역 이동·전법서 습득. 각 폴더의 `build.sh` 로 빌드합니다.
- `소스/옛판_1.0.1/related_officers_rc24` : 15번의 옛 판(1.0.1) 소스입니다. 새 판 파일은 이 소스의 결과를 새 주소로 옮긴 것이라, 그대로 빌드하면 새 판에서는 맞지 않습니다.
- 공용 머리 파일: `mod_api.h`(ModCore와 모듈 사이 약속), `common.h`, `module_hooks.h`.

## 5. 소스가 없는 것

- **통합편의(SAN14_IntegratedConvenience.dll)·22번 DomesticCE** : 처음부터 바이너리만 있던 파일입니다. 대신 표 02~04로 어디를 피하면 되는지 알 수 있습니다.
- **"바이너리만"으로 적힌 모듈** : 1.0.1 판 바이너리를 새 판 주소로 옮긴 것이라 이 판의 소스가 없습니다.
  - 해당: 9번 Traits9/Traits9_UI, Collab, 14번 ModPackBridge/TraitHover, 16번 SortiePresets, 19번 FPS120, 23번 CityCaps, 26번 NoExecute/RoninEscape/AISearch, 27·28·30번 일부, ExtBridge, ModCore와 리졸버.
  - 표 01·05·06에 그중 일부의 자리가 들어 있습니다.
- **8번의 파이썬 런타임 DLL** : 남의 실행 파일이라 넣지 않았습니다.

## 6. 표 01을 볼 때 주의

- 표 01은 실제 게임 기록(ModCore 기록, 새 판 세션 전체)에서 뽑았습니다. 그래서 **그 PC에서 한 번도 켜지 않은 번호의 자리나 ModCore를 거치지 않는 모듈의 자리는 빠져 있습니다**(26·27·28번, 30번 FastMenu 등).
- 같은 자리가 길이가 다르게 두 번 나오면, 판이 바뀌면서 길이가 달라진 것입니다. 긴 쪽을 기준으로 피하세요.
- 원래 바이트는 게임 원본 실행 파일(복호화 판) 기준입니다.

## 7. 이번에 실제로 있었던 예 (AI 전술 모드 v15.9)

- 증상: 시작 종합 진단 R43D-2 — "5번 수행·대열 이동 호환성 검사 실패".
- 원인: AI 모드가 `0x303fc9`의 call(→ `0x185710`)을 자기 쪽으로 돌림 → 표 02의 107번 구간(`0x303ea0`, 484바이트, 확인만) 안이라 통합편의 검사 실패.
- 해결(AI 모드 쪽): 그 한 자리만 2장 방식으로 통합편의 확인이 끝난 뒤에 걸게 함 → 두 기능 다 동작.
