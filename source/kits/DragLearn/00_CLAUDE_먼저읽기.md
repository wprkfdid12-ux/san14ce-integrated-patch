습득창의 **전법서 목록(1안)과 습득무장 목록(2안)**을 게임 자체 다중선택(체크박스) 목록으로 바꾸고, [결정]→[예] 한 번에 **고른 무장 모두에게 고른 전법서 모두**를 차례로 습득시킨다(무장마다 게임이 허용하는 조합만). 비용은 원래대로 습득 1회당 전법서 1·명령서 1.

## 5. 게임 구조 (이 기능이 의존하는 것)
- 습득창: `+478` 세력, `+480` 고른 전법서, `+488` 무장, `+490` 교체 대상 전법(유효하면 교체 모드 = 10칸 다 찬 뒤 지울 전법을 고른 상태), `+4B8` 하위 객체
- 습득 명령(LearnTactic의 rcx, 호출자 스택 rsp+30): `+0` 무장, `+8` 전법서(CGemData), `+10` 교체 대상, `+18` 세력
- LearnTactic(cmd) 반환 int(성공 1). 내부: 기존 칸에서 교체 대상 제외 → 새 전법 추가 → **앞 10개만 기록(넘치면 버려지고 비용은 빠짐)** → 전법서 개수 −1(세력+0x120 word) → 명령서 −비용(0 미만이면 0으로, **부족해도 습득됨**)
- **전법서 개수도 확인하지 않음**(0권이어도 습득, 개수는 0에서 멈춤) → 추가 습득마다 개수 ≥1 확인
- 그래서 추가 습득마다 허용·전법서 개수·명령서·빈 칸을 미리 확인한다(Y). 원래 게임의 명령서 부족 검사는 exe+70A0D0(메시지 0x57C7)
- 허용 판정(목록 회색 규칙과 동일): 전법 t=[표+gem+52], (1) 무장의 10칸 중 f_tid(t)와 같은 번호가 없을 것 (2) 데이터루트 +77428~+774D0의 진형 f 중 valid, id=f_fid(f)≤20, dword [t+6C]의 id 비트가 켜져 있고, (byte [f+7E]==2 이면 f_pspec(무장)==id, 아니면 f_pform(무장,id)≠0)인 것이 있을 것
- 무장 목록(함수 74A240, rbx=습득창): 설정 묶음 rsp+40(+18 방식, +1C 최대, +20 최소), 닫힌 뒤 [rsp+28] = 결과 번호표 포인터. 첫 무장이 창+488로 들어감
- 전법 칸: `f_slot(무장,i)` = 칸 i의 전법 번호(무장+0x130+i). 전법 객체 = `[[데이터루트]+774D0+번호*8]` (번호>200이면 +774D0), `valid(obj)`가 참이면 찬 칸
- 명령서: `f_orders(세력)` → 객체, `byte +14` = 명령서 수. 비용 = `int [비용 전역]`(=1)
- 목록 결과: X 시점 `h=[[rsp+38]]`, `개수=[[개수표]+h*8]`, `첫 칸=[[사슬표]+h*8]`, 칸 `+0`=CGemData*, `+8`=다음 칸, `h < [범위]`
- 전법서 CGemData: `+0` vtable, `+52` 전법 번호. 목록 클래스 `CCmnInfoListBody<CGemData>`, 상태 `CDataSelectState<CGemData>`

## 6. 레지스터·스택 규칙 (스텁을 고칠 때)
- S: 들어올 때 rsp 16정렬(함수 본문). rax rcx rdx r8–r11 자유(바로 뒤 call 30CF80 전). r13=습득창, rdi=1 보존 필수(뒤에서 씀). push 없이 직접 call(정렬 유지)
- X: rax rcx rdx r9 r10 r11 자유(뒤에서 다시 씀). r8은 원래 명령 결과로 남겨야 함
- Y: call을 jmp로 바꿨으므로 진입 rsp는 원래 call 직전과 같음(16정렬). push 7개 + sub 0x28(그림자 영역 0x20 + 지역 1칸)로 정렬 유지. **게임 함수는 자기 그림자 영역(호출자 [rsp..rsp+20))에 레지스터를 저장하므로 push 직후 바로 call하면 저장해 둔 값이 덮인다**(v1의 버그, v2에서 수정, 테스트의 가짜 함수가 그 영역을 일부러 덮어 검사). 반환값 rax는 첫 습득 결과로 복원. cmd +0/+8/+10은 매 호출 뒤 원래 값으로 복원
- P: 함수 본문(5 push + sub 450)이라 16정렬. rbx=습득창, rsi=1 보존. Q: rax rcx rdx r9–r11 자유, [rsp+28] 읽은 뒤 sub rsp,80 임시 버퍼에 읽고 복사(취소 시 이전 선택 유지)
- count_filled: call로 들어오므로 push 3 + sub 0x20으로 정렬 맞춤
- 블록 데이터 순서·이름은 `tools/gen_block.py`의 FIELDS와 맞아야 함

## 7. 다른 모드와 겹칠 수 있는 곳 (호환성 점검 순서)
1. **같은 6곳을 고치는가?** S `7482EC~F4`, X `748359~5F`, Y `740125~29`, P `74A338~41`, Q `74A37A~7F`, D `74816E~74`(한국어판). 겹치면 드래그습득이 스스로 꺼짐(패턴 불일치 → 게임 안 건드림). 반대로 드래그습득이 먼저 설치됐다면 상대 모드의 패턴 검색이 실패할 수 있음
2. **같은 함수를 대신 부르는가?** LearnTactic(1F0520)을 상대 모드가 감싸면(vtable/인라인), 드래그습득의 추가 습득도 그 감싼 함수를 거침(직접 call이라 인라인 후킹이면 거침, 호출부만 바꿨다면 안 거침)
3. **습득창 목록 설정을 바꾸는가?** 같은 CDataSelectState<CGemData> 설정(rbp-48/-44/-40)을 다른 곳에서 덮으면 최대치가 달라짐
4. **로더 이름**: 이 키트의 로더는 `version.dll`. 2026-10 현재 다른 모드: 전장의 안개 = `dinput8.dll`, 발탁 = `xinput1_3.dll`, 롤백 통합패치 = `dinput8`/`dxgi`/`version` + ModCore. 롤백판에서는 로더 대신 ModCore 모듈 ini(`bin/SAN14Mods/modules/DragLearn.ini`)를 쓸 것(롤백판 패턴 일치는 미확인 — 안 맞으면 스스로 꺼짐)
5. **후킹 장부가 있는 모드에 넣을 때**: `DL_Host.patch_group`으로 6곳을 한 묶음(`SAN14CE.DragLearn`)으로 넘길 수 있음
3-2. **습득무장 목록 설정을 바꾸는가?** CDataSelectState<CPersonData>는 32곳에서 쓰이지만 드래그습득이 고치는 건 습득창(74A240) 한 곳뿐
6. 휠클릭(WheelRegion, 같은 제작자) 패치 3곳 `17F590`/`18C4B4`/`231500`과는 겹치지 않음 — `test/combo_test.c`로 4개 언어판 확인, 한국어판 실게임에서 두 DLL 함께 로드·동작 확인(습득창 위 휠클릭도 반응 없음)
