# 게임 패치 뒤 점검 순서 (드래그습득)

게임이 업데이트되면(예: 2026-10-15 패치) 코드 위치가 바뀔 수 있습니다. 드래그습득은 고정 주소 대신 바이트 패턴으로 찾기 때문에 **대개는 그대로 동작**하고, 안 맞으면 **게임을 건드리지 않고 스스로 꺼집니다**(튕기지 않음).

## 1. 사용자 점검 (5분)
1. 게임 실행 → 세이브 불러오기 → 습득창까지 들어갑니다.
2. `<게임>\SAN14Conv\SAN14_DragLearn.log` 를 엽니다.
   - `pattern matches S=1 X=1 Y=1 P=1 Q=1 E1=1 E2=1 D=1 SF=1 XC=1 L1=1 L2=1 L3=1 L4=1 L5=1 L6=1 G=1 X5=1` 그리고 `ready` → **정상**
   - 어느 하나라도 0 또는 2 → 그 패턴이 바뀐 것. 기능은 꺼져 있음 → 아래 2번
   - `game code not found (timeout)` → 실행 파일 구조가 크게 바뀜 → 아래 2번
3. 정상이면 실게임으로 확인:
   - 빈 칸 있는 무장 → 2~3권 체크 → [결정] → [예] → 모두 배워지는지, 전법서·명령서가 권수만큼 줄었는지
   - 명령서가 빈 칸보다 적을 때 그 수까지만 체크되는지
   - 10칸 찬 무장 → 교체 습득이 원래대로(1권) 되는지
   - 습득무장 목록에서 2~3명 체크 → 전법서 1권 → 모두 배우는지, 이미 배운 무장은 건너뛰는지
   - 첫 무장이 이미 가진 전법서도 다른 무장이 배울 수 있으면 목록에서 고를 수 있는지
4. `SAN14Conv\SAN14Conv_loader.log` 에 `loaded SAN14_DragLearn.dll` 이 있는지 (로더 자체 확인)

## 2. 패턴이 안 맞을 때 (Claude에게 맡기는 경우)
Claude에게 이 키트 폴더 + 새 게임 실행 파일(`SAN14CE_KO.exe` 등)을 주고 "패치 후 점검"이라고 하면 됩니다. Claude가 할 일:
1. 새 exe에서 분석용 이미지를 만들고 `00_CLAUDE_먼저읽기.md` 3절의 패턴을 하나씩 검색 → 어느 것이 바뀌었는지 확인
2. 바뀐 곳은 옛 위치 주변 코드와 비교해 새 패턴을 만들고, **한국어판에서 1개만 일치**하는지 확인(다른 언어판은 필요할 때만)
3. 5절의 구조체 오프셋(습득창 +478/+488/+490/+4B8, 명령 +0/+8/+10/+18, 전법표 +774D0, 진형표 +77428, 전법 +6C, 진형 +7E, 명령서 +14, 전법서 개수 세력+120, 무장 목록 rsp+58/+5C/+60/+28 등)이 그대로인지 LearnTactic·목록 함수 디스어셈블로 확인 — 바뀌었다면 `src/dl_block.S` 수정 후 `tools/gen_block.py`
4. `./build.sh`, `./test/run_tests.sh <새 한국어판 이미지>`, `./test/run_combo.sh` 통과 확인
5. `ce/RTK14_gem_test8.CT`의 AOB도 같은 패턴이므로 함께 고치기
6. 문서의 주소 표(00_CLAUDE 4절) 갱신

## 3. 휠클릭과 함께 쓰는 경우
휠클릭 키트도 같은 방식으로 점검합니다(`SAN14_WheelRegion.log`의 `pattern matches A=1 B=1 K1=1 K2=1 G=1`). 두 기능은 서로 독립이라 하나가 꺼져도 다른 하나는 동작합니다.
