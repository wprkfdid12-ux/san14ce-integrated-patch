2. 차기 패치 수정 목표와 우선 조사 지점
- 논공 완료 후 원래 명령 화면으로 복귀하고, 같은 턴에 허용되는 다른 행동을 계속할 수 있어야 한다.
  논공을 마쳤다는 이유만으로 턴 종료/진행 명령을 실행하거나 남은 행동 기회를 소실시키지 않는다.
- 논공에 필요한 정상 비용만 한 번 반영하고 추가 행동력 차감·중복 비용 처리를 방지한다.
- 선택 가능한 논공 대상이나 보상이 없는 경우도 조사 범위에 포함한다. 항목이 없는 화면 진입,
  빈 선택의 확인, 모든 대상 처리 후 복귀가 턴 진행으로 잘못 연결되지 않아야 한다.
  사용자가 실제 논공을 실행하지 않았다면 이 경로에서 논공 비용이나 리롤권을 소모하지 않는다.
- 원작의 정상 턴 종료 조건과 사용자가 직접 실행한 턴 진행은 유지한다.
- 논공 결정 → 보상 반영 → 원작 감사 대사 → 논공 화면 종료 → 메인 복귀의 실제 호출 순서를
  우선 추적한다. 상태/화면 전환의 중복 종료, 잘못된 복귀 대상, 결정·대사 종료 입력의
  메인 화면 전달, 비용/AP 처리와 원작 턴 진행 연결을 확인한다. 모두 조사 가설이며 확정 원인이 아니다.
- R9의 hook_confirm, original_state_tick 및 원작 확인 성공 후 화면 복귀 처리를 조사한다.
  대체 시험에서 화면 종료 함수를 한 번 호출했다는 것만으로 실제 원작 명령 종료와 턴 흐름이
  올바르다고 판단하지 않는다. 아래 AI/버튼 경로를 이 증상의 원인으로 단정해 수정하지 않는다.
- 원작 내정 선택, 두 줄 합계 최대 3칸, 각 줄 왼쪽 우선, 무장별 총 리롤 5회,
  단계별 선택 상태, 뒤로/ESC의 결과 폐기·소모 리롤 유지, 교체 동의창을 보존한다.
- 이번 항목으로 황금 확률·혈연 가중치·리롤 총량 등 밸런스를 변경하지 않는다.

3. 완료 판정에 필요한 확인
- 새 게임에서 다른 행동을 하기 전 논공을 먼저 완료한 뒤 탐색·제안 등 가능한 명령을
  같은 턴에 계속 실행할 수 있는지 확인한다. 다른 행동 일부를 수행한 뒤 논공을 하는 경우도 확인한다.
- 논공 전후의 턴/날짜, 남은 행동력·명령서, 금, 보상 상태를 비교한다.
  정상 논공 비용과 추가 손실을 구분하고 동일 보상/비용이 중복 적용되지 않는지 확인한다.
- 정상 결과, 리롤 후 결과, 꽝, 기존 개성 교체, 내정 보상, 여러 무장 동시 결정 및
  원작 감사 대사가 한 번/여러 번 나오는 경우의 복귀를 확인한다.
- 뒤로/ESC로 취소한 경우에도 의도치 않은 턴 종료가 없는지 확인한다.
- 추가 댓글의 재현 조건을 구분한다: 논공 대상 0명 / 대상은 있으나 선택 가능 보상 0개 /
  미선택 상태 / 마지막 대상 처리 직후 / 전체 행동 소진 상태.
  특히 논공에서 선택할 것은 없어도 탐색·제안 등 다른 행동이 가능한 상태가 유지되는지 확인한다.
  전체 행동 소진 시에는 원작과 동일 조건으로 비교해 정상 자동 진행과 패치 결함을 구분한다.
- 새 게임 반복 진입과 기존 세이브 양쪽에서 검사하고, 입력 누름·해제 및 빠른 연속 입력도 확인한다.
- 정상 AI 논공과 원작의 정상 턴 진행을 막지 않는지 확인한다.
- 합성 이벤트 시험 통과만으로 이번 실제 턴 종료 버그의 해결을 선언하지 않는다.

4. 앞선 조사에서 확인한 별도 방어 점검 사항 — 이번 제보의 원인으로 확정하지 않음
- 화면 표시·갱신·상태 처리만 수행한 대체 환경 시험에서는 추첨 및 확정이 발생하지 않았다.
  기존 윗줄/아랫줄 획득 수 (0,0), (1,0), (0,2), (3,0) 네 조건에서 각 60회 갱신했다.
  이 시험은 실제 게임의 전체 화면 진입·입력 전달을 재현하지 않았으므로 제보를 부정하지 않는다.
- source/runtime_flow.inc의 hook_ai_visit에는 플레이어 직접 조작 대상 제외 검사가 없다.
  이미 획득한 윗줄 칸에 처리 기록이 없으면 ai_process가 자동 추첨·조건부 리롤·적용을 한다.
  화면에 표시된 무장을 이 경로에 직접 전달한 시험에서는 결정 없이 개성 1개가 추가됐다.
  다만 이 AI 후보 처리 경로가 실제 논공 화면 진입 때 호출되는지는 확인되지 않았다.
- hook_button_event는 전달된 보상 버튼 이벤트를 실제 새 사용자 입력인지 별도로 검증하지 않는다.
  화면 갱신의 선택 표시 처리 중 보상 버튼 이벤트를 인위적으로 한 번 전달한 시험에서,
  물리 입력 없이 미리보기 1개·추첨 연출·윗줄 1칸 선택이 생성됐다. 최종 확정은 0회였다.
  이 시험은 내부 이벤트에 대한 방어 여부를 검사한 것이며, 원작 선택 표시 함수가 실제로
  그 이벤트를 발생시킨다는 증거가 아니다. 실제 진입 버그 재현 완료라고 주장하지 않는다.
- 시험은 기존 R9 Win64 DLL을 사용했고 OS/게임의 일부 처리는 대체했다. 실게임 검증은 남았다.

별도 방어 점검 목표(위 턴 종료 결함 조사를 대체하지 않음)
- 논공 화면 열기, 화면 재등록, 행 표시·갱신, 페이지 전환, 무장 선택창 복귀만으로는
  가챠 시작·리롤권 소비·보상 확정·랭크 승격·비용 지출이 일어나지 않아야 한다.
- 화면을 여는 데 사용한 입력과 화면 안에서 새로 수행한 보상 선택 입력을 구분한다.
  초기화/프로그램 내부 통지/오래된 버튼 이벤트를 새 사용자 선택으로 취급하지 않는다.
- 실제 개성 해금 선택으로만 추첨을 시작하고, 최종 적용은 원작 아래 [결정]으로만 수행한다.
  원작이 지원하는 키보드·컨트롤러 입력도 고려한다. 단순 마우스 누름 검사로 정상 입력을 막지 않는다.
- AI 처리 호출 지점과 실제 조작 주체를 검증해 플레이어 직접 조작 무장이 AI 경로에서
  의도치 않게 추첨·교체·확정되지 않도록 분리한다. 정상 AI 논공은 유지한다.

2. 차기 수정 목표와 조사 지점
- 무장이 정상적인 등용·소속 변경을 거쳐도 이미 확정한 가챠 개성과 무장별 리롤 소모,
  단계별 보상 기록, 꽝/X·열정 상태 등 해당 무장의 기록을 일관되게 유지한다.
- 정상적인 소속 변경이나 장기 진행 후 저장·불러오기를 저장정보 불일치/손상으로 오판하지 않아야 한다.
- 사용자 확정: 이번 수정은 고람뿐 아니라 모든 장수에게 공통 적용한다.
  특정 이름/무장 ID만 예외 처리하지 않는다. 플레이어·AI, 일반 무장·군주, 신무장도 적용 범위에 포함한다.
- 등용·귀순·포로 해방·군주 취임/퇴위·세력 멸망 등 신분/소속 변화와 저장·불러오기에서
  원작 논공 값과 패치 보상 이력을 일관되게 해석한다. 이 사건 전부가 원인으로 확인된 것은 아니다.
  이미 획득한 개성, 단계별 확정 기록, 소비한 개인 리롤권, 꽝/X·열정 상태를 유지한다.
- 정당한 원작 상태 변화 때문에 윗줄 획득 수가 내려간 경우를 보조 저장정보 전체 손상과 구분한다.
  원작 값이 0이라는 이유만으로 획득 이력을 지우거나 미추첨으로 되돌리지 않는다.
  무장 한 명의 정상적인 전환을 오판해 전체 장수의 논공과 저장이 막히지 않도록 처리한다.
- 이력 보존은 보상을 다시 지급하거나 사용한 선택 기회를 다시 여는 동작이 아니다.
  확인된 기록을 바탕으로 일관성을 회복하고 중복 보상·리롤 복구·총 3회 초과를 막는다.
  잘못된 세이브 짝이나 실제 손상까지 무조건 허용하도록 검증을 제거하지 않는다.
- 오류창을 띄운 구체적인 검증 실패 사유를 식별한다. 원작 세이브와 보조 저장정보의 짝,
  저장 완료 여부 및 무장별 보상/리롤/꽝 상태의 일치 여부를 실제 자료로 구분한다.
  오류창이 떴다는 이유만으로 원본 세이브 파손, 파일 누락, 특정 무장의 등용을 원인으로 확정하지 않는다.
- 등용 전후의 실제 무장 데이터와 부가 저장정보를 비교하고, 저장 직전·불러오기 직후의
  검증 실패 이유 및 저장/논공 차단 시점을 추적한다.
- 무장 ID 기준 기록 연결, 세력·플레이어/AI 전환 시 상태 처리, 가챠 개성 반영과 보유 개성 검증,
  원작 세이브와 부가 저장정보의 연결을 조사한다. 모두 점검 후보이며 확정 원인이 아니다.
- 확인이 필요한 저장정보를 무조건 정상 처리하거나 오류 경고만 숨기는 방식으로 해결하지 않는다.
  정상 기록을 초기화해 리롤권이 복구되거나 가챠 보상이 중복 지급되는 것도 방지한다.
- 기존 정상 세이브의 호환성을 유지한다. 문제 세이브 복구는 실제 자료로 정합성을 확인한 경우에만 설계한다.

3. 완료 판정에 필요한 확인
- 가챠 개성을 확정한 무장에 대해 등용/소속 변경 전후를 각각 저장하고 불러온다.
- 고람 제보 조건(획득 개성과 확정 기록 유지 / 원작 윗줄 획득 수 1→0)을 재현 조건으로 추가한다.
  고람 외 여러 무장 ID와 플레이어·AI 양쪽에서도 동일 조건을 검사한다.
  1·2·3회 확정, 일반 결과·교체·꽝 및 리롤 소비 이력을 구분해 기록이 유지되는지 확인한다.
  특정 인물에서만 통과하거나, 경고만 사라지고 보상/리롤이 재지급되는 상태는 해결로 인정하지 않는다.
- 새 게임 직후뿐 아니라 여러 차례 논공과 턴 진행을 거친 장기 세이브의 저장·불러오기도 확인한다.
  약 2년 진행 제보를 재현 대상으로 포함하되 검사 범위를 정확히 2년으로 한정하지 않는다.
  등용·소속 변경이 없는 사례도 별도로 비교하고, 자동저장/수동저장 및 반복 덮어쓰기 후 불러오기를 구분한다.
- 게임을 끄지 않고 계속 진행 / 같은 실행 중 불러오기 / 게임 재실행 후 불러오기를 비교한다.
- 아군→적, 적→아군, AI 세력 사이 이동을 구분한다. 관련 조건으로 포로 등용·귀순도 점검한다.
- 원본 개성만 가진 무장을 대조군으로 두고, 가챠 개성 추가·교체·소모 리롤 및 꽝/열정 이력이
  있는 경우의 차이를 확인한다. 등용 직전 미확정 미리보기가 없는 정상 확정 상태부터 검사한다.
- 불러오기 후 자동저장, 수동저장, 논공 진입·선택·확정·취소의 정상 동작을 각각 확인한다.
- 개성, 리롤 잔량, 단계별 기록이 다른 무장/세력으로 섞이거나 복구·중복 지급되지 않는지 확인한다.
- 자동 턴 종료 수정과 함께 적용했을 때에도 저장·논공 흐름이 유지되는지 확인한다.
- 실제 세이브와 로그 없이 오류창 사진만 있는 현재 한계를 표시한다.
  추가 사진으로 경고 내용은 확인했지만 검증 실패 원인이나 실게임 재현/해결까지 확인한 것은 아니다.


[NEXT-003] AI 논공 보상 선택을 윗줄 개성 가챠 우선으로 변경
상태: 사용자 요청 확정 / 차기 구현 대기

1. 목표
- AI가 아랫줄 내정 보상을 자주 선택하는 현재 경향을 바꾸고, 가능한 한 윗줄의
  개성 해금 보상을 선택하도록 한다. AI 군주에게도 동일하게 적용한다.
- 사용자가 예로 든 장료·고순·하후돈·하후연·조인 등 AI 무장이 실제로 가챠를 거쳐
  새로운 개성을 보유한 모습을 볼 수 있게 하는 것이 목적이다. 적용 범위를 이 다섯 무장으로 제한하지 않는다.

2. 선택 규칙
- 적법하게 선택할 수 있는 윗줄 개성 해금이 있으면 이를 기본 우선 선택으로 삼는다.
  원작의 군사/내정 능력 비교만으로 내정 보상을 우선하는 기존 판단을 그대로 두지 않는다.
- 사용자는 '어지간하면 개성 쪽으로 다 선택'을 요청했다. 80%, 90% 같은 비율을 합의된 수치로 만들지 않는다.
  개성 쪽을 선택할 수 없는 경우 등에 한해 내정 선택으로 정상 진행할 수 있도록 설계한다.
- 이미 선택된 보상, 공로/랭크 조건, 두 줄 합계 최대 3칸, 각 줄 왼쪽 우선 규칙을 지킨다.
  앞칸을 건너뛰거나 내정 보상에 개성 보상을 추가하여 총량을 초과하지 않는다.
- 개성칸이 이미 가득 찬 AI 무장은 윗줄 개성 보상을 선택하지 않고, 선택 가능한 아랫줄 내정 보상을 선택한다.
  스타 여부와 군주 여부에 관계없이 적용한다. 해당 AI에게 승계/교체를 시켜 빈칸을 만들지 않는다.
  이 규칙은 종전의 "9개성 AI도 승계/안전교체로 개성을 우선" 지시를 대체한다.
- 빈칸이 있는 AI는 윗줄 개성을 우선한다. 각 보상을 선택하기 전에 추가 가능한 빈칸을 다시 확인한다.
  같은 논공 처리 중 앞선 개성 보상으로 마지막 빈칸을 사용했다면 이후 선택은 내정으로 전환한다.
  여러 칸을 묶어서 결정할 때도 앞선 선택 결과를 반영해 공간을 초과하는 개성 선택을 예약하지 않는다.
- 이 만석 제외 규칙은 AI의 선택 정책이다. 플레이어의 기존 9개성 승계/스타 안전교체 기능은 유지한다.
- 기존 가챠 후보·확률·중복/충돌 제외·꽝·열정 및 무장별 총 리롤 5회 규칙을 적용한다.
  특정 개성이나 황금 개성을 고정 지급하는 변경은 아니다.
- 플레이어의 보상 선택은 수동으로 유지한다. 이 AI 우선순위를 플레이어의 무장에 자동 적용하지 않는다.
- 이미 확정된 내정 보상을 소급하여 지우고 개성으로 재배분하는 정책은 이번 요청에 포함해 실행하지 않는다.

3. 검사
- 예시 다섯 무장과 내정 성향 AI 무장, AI 군주가 빈칸이 있을 때 유효한 윗줄을 우선 선택하는지 확인한다.
- 처음부터 9칸이 가득 찬 AI는 내정을 선택하고 개성 추첨·교체·리롤을 시작하지 않는지 확인한다.
  8칸에서 시작해 한 칸 추가로 가득 찬 경우 다음 선택은 내정으로 전환되는지 확인한다.
  같은 처리에서 여러 보상을 선택하는 경우에도 이 규칙을 지키고 두 줄 합계 3칸을 넘지 않아야 한다.
- 내정 선택으로 넘어간 경우의 이유를 확인하고, 개성 확정 후 보유 목록·툴팁·저장/불러오기에 반영되는지 검사한다.
- AI 선택 처리와 플레이어 화면 조작이 서로 간섭하지 않는지 확인한다.


[NEXT-004] 플레이어·AI 군주를 논공 대상에 포함하고 처음부터 중진 기준 적용
상태: 사용자 요청 확정 / 차기 구현 대기

1. 대상과 중진 처리
- 플레이어 군주와 AI 군주 모두 논공 대상에 포함한다.
- 군주는 처음부터 중진으로 취급해 숙련·노련·중진에 해당하는 총 3회의 보상 선택 기회를 즉시 사용할 수 있게 한다.
  공로를 더 쌓거나 별도로 랭크를 해금하는 선행 절차를 요구하지 않는다.
  표시만 중진으로 바꾸거나, 세 보상을 이미 받은 것으로 처리해 선택권을 없애지 않는다.
  중진 자격 부여 자체와 보상 선택/확정은 분리한다. 통상적인 논공 비용은 기존 규칙을 유지한다.
- 두 줄을 합쳐 최대 3칸이라는 공통 규칙을 따른다. 윗줄 3칸과 아랫줄 3칸을 각각 지급하지 않는다.
  각 줄은 왼쪽부터 선택한다. 이미 확정한 보상이 있다면 남은 횟수만 사용한다.
- 일반 무장 전체를 중진으로 만드는 변경은 아니다. 군주로서 부여받은 중진 자격은 이후 신분이 바뀌어도 유지한다.
  예: 마등이 군주였다가 세력이 멸망하고 유비 휘하 일반 무장이 되어도 중진으로 취급한다.
  이미 받은 보상과 남아 있는 선택 횟수를 그대로 이어가며, 신분 변경을 이유로 랭크를 낮추거나 재해금을 요구하지 않는다.
  다시 군주가 되어도 선택 기회나 리롤권을 추가 지급하지 않는다.

2. 조작·확정·기록
- 플레이어 군주는 다른 플레이어 무장과 마찬가지로 개성/내정을 직접 선택하고 아래 [결정]으로 확정한다.
  군주가 목록에 등장하거나 중진으로 판정되는 것만으로 추첨·확정하지 않는다.
- AI 군주는 NEXT-003에 따라 빈칸이 있는 동안 개성 가챠를 우선 선택한다.
  이미 개성칸이 가득 찼거나 선택 도중 가득 차면 AI 일반 무장과 동일하게 내정을 선택한다.
- 군주도 개성 9칸, 꽝·열정, 무장별 총 리롤 5회 등 공통 규칙을 적용한다.
  플레이어 군주는 기존 승계/스타 안전교체가 가능하며, AI 군주는 위 만석 제외 정책을 따른다.
- 저장/불러오기나 군주 교체·취임/퇴위·소속 변경으로 같은 무장의 보상 기회와 리롤권이 다시 지급되지 않아야 한다.
  군주 여부가 바뀌어도 중진 자격, 확정 보상, 미사용 선택 기회와 소비 기록은 무장 ID에 따라 유지한다.
- 군주 처리에 원작 신분/논공 대상 제외 조건과 랭크 판정이 함께 관여할 수 있으므로,
  목록·선택·비용·확정·감사 대사·복귀·저장까지 실제로 이어지는지 점검한다. 문구 변경만으로 완료 처리하지 않는다.
  군주 한 명의 자격 판정이 어긋나 함께 선택한 다른 무장까지 결정 불능이 되는 경우를 막는다.
  이는 구현자가 해결해야 할 기술적 일관성 문제이며 사용자에게 코드 구조나 후킹 방식을 결정하도록 요구하지 않는다.

3. 검사
- 새 게임의 플레이어 군주와 AI 군주, 기존 세이브의 군주, 플레이 중 새로 취임한 군주를 검사한다.
- 처음부터 총 3칸 선택 기회가 열리고 선택/확정한 만큼만 소모되는지 확인한다.
- 플레이어 군주가 내정과 개성을 섞어 고르는 경우, 개성 9개로 시작하는 경우, 여러 무장과 함께 논공하는 경우도 확인한다.
- AI 군주는 빈칸이 있으면 개성, 가득 찼으면 내정을 선택하며 앞선 선택으로 가득 차는 경우도 처리해야 한다.
- 군주였던 마등이 유비 휘하 일반 무장으로 바뀐 뒤에도 중진 자격과 기존 선택/소비 기록이 유지되는지 확인한다.
  남은 선택이 3회/일부/0회인 경우와 이후 저장·불러오기·재취임을 검사한다.
- NEXT-001의 자동 턴 종료와 NEXT-002의 저장 차단이 군주에게 재발하지 않는지 함께 검사한다.


[NEXT-005] DLC·콜라보 전용 개성의 가챠 후보 누락 보완
상태: 사용자 요청 확정 / R9 데이터·코드 확인 / 차기 구현 대기
목적: 기존 제안서의 '공식 DLC·콜라보 개성도 동일한 적합도 엔진으로 추첨' 요구를 실제로 충족한다.

1. 현재 확인한 문제
- R9에는 개성 마스터 219종의 이름·분류·효과가 있지만, 비교에 쓰는 무장 자료는
  공식 기본 무장 1,000명과 공식 보너스 무장 88명으로 생성돼 있다.
- 그 1,088명의 원본 개성 목록을 집계하면 아래 황금 분류 39종은 보유자가 0명이다.
  source/official_db.h의 해당 항목도 holders=0, anchor=0이다.
- source/gacha.c의 g_distribution은 원본 보유자 유사도·단일 보유자 앵커·혈연 자료에서
  raw 가중치를 만들고, raw가 0인 개성은 후보에서 제외한다. 아래 39종은 현 자료로 가중치가 생기지 않는다.
- source/merit_runtime.c의 pool_for에도 holders 또는 anchor가 있어야 하는 조건이 있다.
  따라서 이름을 표시하거나 편집에서 개성을 해금하는 것만으로는 추첨 후보에 연결되지 않는다.
- 이변/초월도 이미 만들어진 유효 후보의 가중치를 조정하므로 이 누락을 해결하지 않는다.
- 이것은 배포 R9 소스/동봉 DB에서 확인한 후보 누락이다. 이번 확인으로 DLL을 수정한 것은 아니다.

2. 보완 대상 39종
- ID 155~180 (26종):
  155 연금 / 156 남아 / 157 열독 / 158 영애 / 159 식견 / 160 정령 /
  161 상승 / 162 반신 / 163 불패 / 164 준영 / 165 냉철 / 166 질풍 /
  167 지용 / 168 선견 / 169 선배 / 170 대담 / 171 단심 / 172 후배 /
  173 흑기 / 174 용자 / 175 자애 / 176 명문 / 177 숙장 / 178 공전 /
  179 궤변 / 180 자존
- ID 197~200 (4종): 197 추적 / 198 탈주 / 199 헌신 / 200 활기
- ID 202~210 (9종):
  202 숙녀 / 203 구도 / 204 학사 / 205 고귀 / 206 탐구 /
  207 자연 / 208 도식 / 209 구제 / 210 타락
- 이는 이번 R9 자료에서 원본 보유자가 없는 황금 분류 개성 목록이다.
  모든 DLC 개성이 누락됐다는 뜻은 아니다. 이미 정상 후보인 기존/추가 개성도 유지한다.
- 항목별 실제 공식 보유자와 출처를 확인한다. 이름만 보고 콜라보 작품이나 캐릭터를 임의 대응시키지 않는다.

3. 데이터 연결과 추첨 규칙
- 실제 공식 DLC·콜라보 캐릭터의 원본 능력치·원본 개성 등 필요한 마스터 자료를 확보하고
  비교 대상에 연결한다. 캐릭터가 현재 시나리오에 등장하지 않아도 해당 공식 자료로 비교할 수 있게 한다.
- 한 명의 공식 캐릭터만 가진 개성은 그 캐릭터를 앵커로 삼아 기존 단일 보유자 보완 규칙을 적용한다.
  보유자 수·희소성·앵커 정보와 실제 비교 데이터가 서로 일치하도록 생성한다.
- 보유자가 없다고 가상의 장수/능력치/혈연/개성을 만들거나, 현재 아무 장수에게 편집해 준 값을
  공식 원본으로 간주하지 않는다. 이름만 있는 항목에 임의 고정 확률을 붙이는 방식도 사용하지 않는다.
- 자료가 부족한 항목은 누락된 원본 자료와 영향 범위를 정확히 보고한다.
  후보 이름만 등록한 상태를 '39종 추첨 가능'이라고 완료 처리하지 않는다.
- 기존과 동일한 능력치 분포·개성 유사도·혈연·희소성·황금/스타·성장예산·열기·열정 보정을 적용한다.
  콜라보만 별도 고정 지급, 별도 2% 추첨, 황금 확정 보상 등 새로운 확률 규칙을 만들지 않는다.
- 대상/비교 무장의 공식 원본 DB 능력치 사용 원칙을 유지한다. 실제 편집·성장 능력치를 변경하지 않는다.
- 실제 설치된 게임에서 유효한 이름/분류/효과를 가진 개성만 연결한다.
  중복 보유·상충 후보 제외, 실제 개성 ID 사용, 9칸 수용량과 AI 만석 제외 규칙을 유지한다.
- 후보 추가 자체로 정규화 후 황금 비율이 달라질 수 있다. 같은 장수/보유 개성/보상 이력 조건으로
  변경 전후의 황금 합계 확률과 콜라보 합계 확률을 비교해 보고한다.
  이번 보완을 구실로 기존 황금 배율이나 리롤 총량을 임의로 상향하지 않는다.

4. 구현 점검 지점
- data/SAN14CE_개성마스터219_DB.json 및 공식 무장 자료의 출처/보유자 집계,
  source/generate_db.py, source/official_db.h, source/gacha.h, source/gacha.c,
  source/merit_runtime.c의 후보 생성·runtime 유효성 검사를 함께 확인한다.
- 현재 1,088명 및 기본 무장 1,000명에 고정된 배열/루프, 무장 ID와 배열 인덱스의 대응,
  앵커 조회를 점검한다. 새 공식 캐릭터의 ID를 억지로 기존 장수에게 재사용하지 않는다.
- pool_for 목록만 늘리거나 installed_colors만 바꾸고 실제 g_distribution이 여전히 0을 만드는
  불완전한 수정이 되지 않도록, 실제 추첨 엔진까지 연결됐는지 확인한다.
- 결과 이름·황금 분류·효과·개성 9칸 표시·Hover·계산 근거·6단계 평가·사건 로그를 일관되게 연결한다.
  기존 Hover의 실제 개성 ID와 설명을 사용한다.
- 기존 세이브의 확정 결과를 재추첨하거나, 기존 개성을 삭제하거나, 리롤/보상 이력을 초기화하지 않는다.
  보완된 새 후보는 이후 적법한 추첨에 반영하고, 얻은 콜라보 개성은 저장/불러오기 후에도 유지한다.
- NEXT-002의 저장 검증 보완과 함께, 콜라보 개성 보유 장수의 등용·소속/신분 변경을 점검한다.

5. 완료 판정
- 39종 각각의 공식 출처·보유자·앵커 연결을 확인하고, 이름/효과만 존재하는 항목과 구분한다.
- 설치 데이터가 유효하고 중복·상충으로 제외되지 않는 적법한 표본 조건에서
  각 개성의 실제 최종 가중치가 양수이며 추첨으로 도달 가능한지 검증한다.
  특정 무장이 이미 보유했거나 상충하는 경우 후보에서 빠지는 정상 동작도 확인한다.
- 몇십 번 뽑아 한 번 나왔거나 안 나왔다는 결과만으로 전체 39종의 연결을 판정하지 않는다.
  실제 후보 분포 검사와 추첨 결과 적용 검사를 구분한다.
- 플레이어/AI 양쪽에서 실제 개성 기능·호버·저장/불러오기와 보상 기록 유지 여부를 확인한다.
- 원작 내정 선택, 총 3회/왼쪽 우선, 무장별 총 리롤 5회, 꽝/열정 및 기존 다른 패치 연동을 보존한다.
- 공식 원본 자료나 실게임 검증이 부족하면 그 한계를 명시한다. 미완료를 완료로 보고하지 않는다.

공통 상태: NEXT-001~005는 차기 패치 최종 추가수정 제안이다.
구현·실게임 검증은 대기 상태이며, 이 문서 갱신만으로 R9 코드·DLL·설치 ZIP은 변경되지 않았다.
