1. 최우선 버그: 순정 감사 대사/일러스트 후 게임 튕김
====================
사용자 실게임 재현:
- 조광으로 논공 가챠 실행 -> 결과 확정됨.
- 의도된 정상 흐름은: 가챠 결과 확정 후, 논공 화면 하단의 '확인/결정'을 눌렀을 때에만 순정 장수 일러스트 + 장수의 원래 '감사합니다' 계열 논공 메시지가 떠야 함.
- 실제 R1에서는 가챠가 끝난 개성 해금 칸 자체를 다시 클릭했을 때 순정 감사 메시지와 일러스트가 먼저 뜸.
- 그 뒤 게임이 멈춘 후 크래시.

반드시 수정:
A) '가챠 결과 칸 클릭'과 '하단 확인/결정' 이벤트를 완전히 분리한다.
B) 가챠 완료 칸을 클릭해도 순정 일러스트/감사 대사를 절대 호출하지 않는다.
C) 순정 일러스트/대사는 최종적으로 하단 확인/결정을 눌렀을 때 1회만 원작 흐름으로 호출한다.
D) R1에 존재할 수 있는 강제 화면 상태 변경, 원작 갱신 함수 재호출, 중복 finalize/return-to-vanilla 호출을 제거한다.
E) 대사 종료 뒤 원작 화면 복귀를 패치가 두 번 처리하지 않도록 한다.
F) 동일 장수/동일 칸에서 더블클릭, 연타, 재진입을 포함한 중복 호출 방지 guard를 둔다.

- 두 번째 개성 해금 칸 자리를 재추첨 버튼으로 사용한 것으로 보임.
- 세 번째 개성 해금 칸 자리를 확정 버튼으로 사용한 것으로 보임.

반드시 수정:

- 2번째/3번째 칸 위에 재추첨/확정 UI를 덮어쓰거나 대체하지 말 것.
- 1/2/3 칸은 '평생 3회의 개성 해금권'이라는 동일한 기능 단위다.
- 3번째 황금 확정 같은 별도 등급 규칙을 만들지 말 것.

4. 개성 해금 칸 클릭 즉시 가챠 시작
====================
R1 문제:
- '개성 해금' 칸을 누르면 선택 색만 바뀌고, 하단 확인/결정을 또 눌러야 가챠가 시작됨.

반드시 수정:
- 해금 가능한 '개성 해금' 칸을 클릭하는 순간 가챠 계산 + 1.2초 연출을 바로 시작.
- 가챠 시작용 추가 확인 버튼을 요구하지 말 것.
- 하단 확인/결정은 가챠 '시작' 버튼이 아니라, 최종 획득 결과를 받아들여 원작 논공 확정 흐름으로 넘어가는 최종 단계로만 사용.
- 연출 중 중복 클릭/다른 해금칸 클릭/재추첨/확정은 안전하게 막는다.

5. 순정 승진/공로 해금 조건 보존
====================
사용자 요구:
- 처음부터 개성 3칸을 전부 열면 안 됨.
- 가용 -> 중견 -> 숙련 -> 노련 -> 중진 등 원래 논공/승진 진행과 보상 플래그가 충족될 때 해당 개성 해금권이 열려야 함.
- 공로 랭크 이름만 보고 임의 추정하지 말고 실제 원본 보상/공로효과 플래그를 읽을 것.
- 시나리오 시작 시 원래 지휘병사 보상이 이미 활성화된 경우에만 대응 개성 해금권을 '열림/미추첨'으로 변환하는 기존 알고리즘 원칙은 유지.
- 아직 원작 조건이 안 된 2/3번째 칸은 잠금 표시와 입력 비활성을 그대로 유지.

6. '계산 근거 펼치기/접기' UI 신규 구현
====================
배치:
- '대상 무장' 영역 바로 아래의 빈 공간.
- 기본 상태: 작은 [계산 근거 펼치기] 버튼 1개.
- 펼치면 같은 영역 안에 진단 내용을 표시하고 버튼 텍스트를 [계산 근거 접기]로 변경.
- 별도 팝업/별도 전체창 금지.
- 기존 초상화/논공 트리를 덮거나 밀어내지 않는 범위에서 구현.
- 내용이 길면 해당 진단 영역 내부만 스크롤.

동작 원칙:
- 펼치기/접기로 RNG 소비 금지.
- 펼치기/접기로 후보 재계산 금지.
- 이미 해당 Roll에서 계산된 snapshot/log 값을 읽어 표시.
- 가챠 연출 중에는 최종 결과를 미리 알 수 있는 값/개성명을 숨김.
- 결과 공개 후 해당 Roll의 계산 근거를 갱신.
- 잠긴 해금칸은 '원작 해금 조건 미충족 / 아직 추첨 안 함'으로 표시.

표시 항목 권장:
1) 해금 조건: 현재 칸, 원작 조건 충족 여부, 실제 원작 보상 플래그 상태
2) 입력 데이터: 통솔/무력/지력/정치/매력, 현재 개성, 슬롯 수
3) 스타: 고유전법 기반 스타 여부
4) 혈연: 부모/조부모 참고 여부와 적용 강도
5) 유사 무장 상위군 + 유사도
6) 후보 개성 상위 가중치
7) 선택 개성 raw/final weight
8) 황금 여부, 공식 희소도 보정
9) 성장예산 전/후
10) 열기 전/후
11) 이변/초월 여부
12) 재추첨 사용/잔여
13) Roll ID + seed hash(원시 seed 노출은 필요 여부 판단)
14) 계산시간 ms

기존 event_log.inc에서 이미 사건 로그로 기록하려던 값을 재사용해 UI 표시용 snapshot을 만들고, UI 때문에 DB를 다시 전체 검색하지 말 것.

7. 계산 근거 마지막에 6단계 '이번 가챠 평가' 추가 (사용자 아이디어, 기준은 아직 최종 승인 전)
====================
표시 순서:
평범 -> 무난 -> 의외 -> 대박 -> 파격 -> 충격

중요:
- 과거 설계에서 금지한 '개성별 수동 등급표'를 만들면 안 된다.
- 질풍=80점, 통찰=95점 같은 수작업 점수 금지.
- 이번 결과의 '상대적 가치 + 희귀성 + 예상 밖 정도'를 현재 후보 분포와 공식 플래그에서 자동 산출해야 한다.

추천 평가식(초안, 사용자 최종 승인 필요):
A. 가치 백분위(Value Percentile) 50%
   - 현재 후보군 안에서 내부 성장비용/AI 효용/고점 지표의 상대 백분위.
   - 수동 개성 점수표가 아니라 이미 알고리즘이 사용하는 내부 객관값을 사용.
B. 놀라움 백분위(Surprise) 25%
   - 최종 후보 선택확률/최종 가중치가 낮을수록 높은 값.
   - 단, 단순 부적합 쓰레기 결과가 '충격'이 되는 것을 막기 위해 가치와 결합.
C. 공식 희소성(Rarity) 15%
   - 공식 교사 데이터에서 보유자 수/희소도 기반. 강함 판정 그 자체가 아니라 보조 지표.
D. 특수사건 10%
   - 황금/이변/초월의 객관 플래그. 초월은 특별 override 가능.

추천 점수 구간(초안):
0~24  = 평범
25~44 = 무난
45~64 = 의외
65~81 = 대박
82~94 = 파격
95~100 = 충격

추천 override(초안):
- 초월 발생 + 가치 백분위가 충분히 높음: 최소 '충격'
- 이변 + 고가치/황금: 최소 '파격'
- 황금 하나만으로는 대박/파격을 보장하지 않음
- 저가치인데 희귀하기만 한 결과가 상위 평가로 튀지 않도록 Value gate 적용

이 평가 문구는 확률을 바꾸는 기능이 아니라 관측/설명 계층이어야 한다.
사용자에게 실제 구현 전에 이 초안을 보여주고 필요하면 기준을 조정할 수 있다.
