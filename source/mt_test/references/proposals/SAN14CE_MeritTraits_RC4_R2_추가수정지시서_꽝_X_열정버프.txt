삼국지14 논공 개성가챠 RC4 R2
꽝 · X 점유칸 · 열정 버프 추가 수정지시서

문서 성격: 기존 R2에만 덧붙이는 증분 변경 명세
작성 기준: 2026-09-19

===============================================================================
0. 가장 중요한 작업 지시 — 처음부터 다시 만들지 말 것
===============================================================================

이 문서는 기존 제안서를 다시 합친 통합 제안서가 아니다.
현재 완성되어 있는 RC4 R2를 유지한 채, 아래의 "꽝 / X 점유칸 / 열정 버프"
기능만 추가하기 위한 후속 수정지시서다.

[기준 작업물]
- 설치본: SAN14CE_MeritTraits_RC4_R2_Install.zip
- 소스본: SAN14CE_MeritTraits_RC4_R2_Source.zip
- 인계 지침: CONTINUE_PROMPT_KO.txt
- 현재 흐름: 해금칸 추첨 → 미리보기 → 별도 확정 → 원래 하단 결정 → 실제 반영

[절대 금지]
- 새 프로젝트를 만들거나 패치를 처음부터 다시 작성하지 않는다.
- 기존 알고리즘 제안서와 인터페이스 제안서를 다시 합쳐 새 설계로 치환하지 않는다.
- 이미 완료된 R2 코드, 후킹, 저장 구조, 원작 UI 흐름을 통째로 교체하지 않는다.
- 기존 정상 기능을 이번 기능에 맞춘다는 이유로 재설계하지 않는다.
- 기존 결과나 이전 저장을 재추첨하지 않는다.

[허용되는 작업 방식]
- 현재 R2 소스 트리에서 필요한 부분만 최소 수정한다.
- 기존 결과형·저장 저널·UI 생성/정리 수명에 필드와 분기만 증분 추가한다.
- 수정된 소스를 컴파일하는 것은 필요하지만, 이는 "처음부터 재구축"이 아니라
  기존 R2 소스에 대한 정상적인 증분 수정·재컴파일이어야 한다.
- 기존 R2 테스트는 그대로 유지하고, 이번 기능의 회귀 테스트만 추가한다.

===============================================================================
1. 이번 수정에서 건드리지 않는 R2 확정 규칙
===============================================================================

아래 항목은 이번 변경의 대상이 아니며 그대로 유지한다.

1) 공식 무장의 가챠 비교 입력은 대상 무장과 비교 무장 모두 원래 DB 능력치를 쓴다.
   예: 조광(ID 619)은 통솔65 / 무력68 / 지력53 / 정치51 / 매력60을 사용한다.
2) 편집·성장으로 바뀐 실제 게임 능력치는 읽어 덮거나 되돌리지 않는다.
3) DB 행이 없는 신무장만 현재 기본 능력치를 fallback으로 사용한다.
4) 현재 보유 개성, 고유전법, 부모 정보는 기존 live 처리 규칙을 유지한다.
5) 기존의 세 번 논공 기회와 원작 하단 결정 흐름을 유지한다.
   단, 재추첨권은 전체 공용이 아니다. 가챠 대상 무장 한 명마다 개인 재추첨권 5개를
   독립적으로 보유하며, 그 무장의 세 번 논공 기회 안에서만 함께 사용한다.
6) 미확정 선택 중 저장 차단, 확정된 기존 결과 재추첨 금지 규칙을 유지한다.
7) 계산 근거 접기/펼치기, Hover, 약 1.2초 추첨 연출, 원작 네이티브 UI를 유지한다.
8) 6단계 평가는 관찰·설명용이며 가챠 확률을 역으로 바꾸지 않는다.
9) 기존의 "열기(낮은 결과 수락 보정)"와 이번 "열정 버프(꽝 확정 보정)"는
   서로 다른 상태다. 둘을 합치거나 이름만 바꿔 재사용하지 않는다.

===============================================================================
2. 꽝 결과의 정의와 발생 조건
===============================================================================

1) 추첨 결과형에 실제 개성과 별개의 결과 `MISS(꽝)`를 추가한다.
2) 꽝은 개성 ID가 아니다. 빈 ID, 임시 ID, 사용하지 않는 개성 ID를 꽝처럼
   위장해서 넣지 않는다.
3) 꽝 확률은 낮은 확률로 둔다. 정확한 기본 확률은 한 곳의 조정값으로 분리하고,
   실게임 분포 확인 전 이 문서에서 고정 수치로 못 박지 않는다.
4) 원작/UI 기준 세 번째(마지막) 논공 보상칸의 꽝 확률은 0이다.
5) 보상칸을 순서와 다르게 처리할 수 있는 예외 경로가 있다면, 실제로 마지막 한 번만
   남은 논공 기회도 꽝 확률을 0으로 처리한다. 열정 버프를 받을 다음 기회가 없는
   상태에서 꽝이 확정되는 모순을 막기 위한 안전 규칙이다.
6) 마지막 칸의 꽝 제거는 황금 개성 확정이나 고등급 확정을 뜻하지 않는다.
   꽝만 후보에서 제외하고 나머지 R2 분포는 그대로 유지한다.
7) 꽝이 화면에 나온 것만으로는 아무 상태도 적용하지 않는다.
8) 사용자가 꽝을 재추첨하거나 취소하면 일반 재추첨/취소로 끝난다.
   이 경우 X 점유칸도, 열정 버프도 생기지 않는다.
9) 사용자가 별도 확정 버튼으로 꽝을 의도적으로 선택하고, 원래 하단 결정까지
   정상적으로 완료했을 때만 꽝을 최종 반영한다.
10) 별도 확정 뒤 하단 결정을 취소하거나 화면을 정상 취소한 경우에도 최종 반영 전이면
    X와 열정 버프를 만들지 않는다.

[재추첨권 소유 범위 — 무장별 5개]

1) 가챠 대상 무장 한 명마다 재추첨권 5개를 따로 부여한다.
2) 이 5개는 해당 무장의 세 번 논공 보상칸에서만 사용한다.
3) 한 무장이 재추첨권을 사용해도 다른 무장의 잔여 횟수에는 전혀 영향이 없어야 한다.
   예: 조광이 2개를 사용하면 조광은 3개, 관우와 장비는 각각 5개 그대로다.
4) 같은 페이지에 여러 무장이 등록되어 있어도 페이지 단위·목록 단위·세력 단위로
   재추첨권을 공유하지 않는다.
5) 페이지를 앞뒤로 바꾸거나 다른 무장을 선택할 때는 선택된 무장의 고유 ID로 잔여
   재추첨권을 다시 읽어 표시한다. 화면 row 번호나 현재 페이지 번호를 키로 쓰지 않는다.
6) 플레이어 무장과 AI 무장 모두 같은 원칙으로 각자 5개를 가진다.
7) 무장을 바꾸는 순간 직전 무장의 잔여 횟수가 새 무장에게 복사되거나 UI 캐시에
   남아 보이면 안 된다.
8) 기존에 전역/페이지 공용 재추첨 변수가 있다면 새 시스템을 따로 만드는 대신,
   현재 저장 구조 안에서 `officer_id → remaining_rerolls(0~5)`의 무장별 상태로
   최소 변경한다.

===============================================================================
3. 꽝 확정 시 X 점유칸 처리
===============================================================================

[빈 개성칸이 하나 이상 있는 경우]

1) 꽝을 최종 반영하면 빈 개성칸 하나를 X 표시로 점유한다.
2) X는 실제 개성 한 칸을 소모한 것으로 취급한다.
3) 이후 이 패치의 개성 수용량 계산은 `실제 개성 수 + X 점유칸 수`를 사용한다.
4) X는 시각적 점유 정보일 뿐 실제 개성은 아니다.
5) X에는 능력, 효과, 발동, 중복 판정, 상충 판정, 교사 유사도, 후보 가중치가 없다.
6) X를 가짜 개성 ID로 보관하지 말고, 무장별 별도 X 슬롯 마스크 또는 동등한
   sidecar 상태로 저장한다.

[이미 실제 개성이 9/9로 가득 찬 경우]

1) 꽝 때문에 기존 개성을 삭제하거나 교체하지 않는다.
2) 실제 개성 위에 X를 덮어씌우지 않는다.
3) 보상 기회는 그대로 꽝으로 끝내고, 논공 결과칸에는 X/꽝 결과를 표시한다.
4) 개성 화면의 기존 9개 실제 개성은 그대로 둔다. 들어갈 빈 칸이 없으므로
   개성칸 X를 억지로 추가하지 않는다.
5) 이 경우에도 꽝을 확정한 대가인 열정 버프는 정상 부여한다.

[편집 및 다른 패치와의 충돌]

1) 사실무장 편집이나 다른 경로가 X로 예약된 위치에 실제 개성을 넣으면 실제 개성이
   항상 우선한다.
2) 해당 X 표시는 즉시 제거하고 저장 상태도 정리한다. 기존 실제 개성을 지우거나
   X를 다른 칸으로 밀어 넣지 않는다.
3) 로드 및 화면 진입 때마다 실제 개성 배열과 X 마스크를 가볍게 대조하여,
   실제 개성과 X가 한 위치를 동시에 차지하는 상태를 남기지 않는다.

===============================================================================
4. X 표시 UI 규칙
===============================================================================

1) X는 논공창 한 곳만이 아니라 개성칸을 보여 주는 모든 화면에서 보여야 한다.
2) 우선 게임 안에서 이미 사용하는 비활성/불가/삭제 계열의 X 표시 리소스를 찾아
   원작 크기와 색감을 그대로 차용한다.
3) 공용 원작 리소스를 빌렸다면 소유권을 가져오거나 직접 파괴하지 않는다.
4) 적절한 원작 X 리소스가 정말 없을 때만, 게임 폰트에서 정상 렌더링이 확인된 X 문자를
   같은 칸 중앙에 표시한다. 확인되지 않은 외부 이미지나 새 디자인은 넣지 않는다.
5) X 칸 Hover에서는 정상 개성 정보 조회를 호출하지 않는다.
6) X 칸 Hover 문구는 고정 안내인 `꽝으로 소모된 개성칸`만 표시한다.
   해당 화면이 안전한 고정 안내 Tooltip을 지원하지 않으면 잘못된 개성 Tooltip을
   띄우는 대신 Hover 설명을 생략한다.
7) 화면 닫기, 재진입, 스크롤, 무장 변경, 로드 때 X 위젯이 중복 생성되거나 이전 무장의
   위치에 남지 않도록 기존 위젯 정리 수명을 따른다.

===============================================================================
5. 열정 버프 — 꽝 확정의 대가로 주는 다음 기회 보정
===============================================================================

1) 사용자가 꽝을 최종 확정했을 때 해당 무장에게 `열정 버프`를 1회 부여한다.
2) 열정 버프는 무장별 상태다. 다른 무장에게 넘어가거나 세력 전체에 공유되지 않는다.
3) AI 무장과 플레이어 무장도 각각 자기 상태만 사용한다.
4) 열정 버프는 해당 무장의 시간순 다음 논공 추첨 기회에 적용한다.
5) 열정 버프가 적용되는 다음 기회에서는 꽝 확률을 0으로 하여 연속 꽝을 막는다.
6) 기존 적합도/후보 가중치를 이용해 높은 적합도 후보와 공식 황금 후보가 나올 확률을
   평소보다 높인다.
7) 이를 위해 별도의 수동 개성 등급표를 새로 만들지 않는다.
8) 6단계 결과 평가(평범~충격)는 사후 설명용이므로 열정 버프의 확률 입력으로 쓰지 않는다.
9) 정확한 가중 배수와 황금 보정치는 한 곳의 조정값으로 분리한다. 실게임 검증 전에는
   제안서의 임의 숫자를 하드코딩된 최종값으로 취급하지 않는다.
10) 열정 버프는 다음 기회에서 결과를 재추첨해도 유지한다. 그 기회에서 실제 개성을
    선택하고 원래 하단 결정으로 최종 반영할 때 한 번 소모한다.
11) 다음 기회 화면을 취소하거나 확정 전에 나가면 버프는 소모하지 않는다.
12) 저장 후 로드하거나 게임을 재실행해도 무장별 열정 버프가 유지되어야 한다.
13) 기존의 열기 상태와 열정 버프가 동시에 존재할 수 있다. 각 보정은 기존 중앙 확률
    조립 단계에서 명시적으로 합성하되, 상태값과 로그는 서로 분리한다.

===============================================================================
6. 꽝 안내창과 입력 처리
===============================================================================

1) 꽝이 추첨되면 약 1.2초의 기존 결과 연출이 완전히 끝난 뒤 안내창을 한 번 띄운다.
2) 버튼 Release 콜백 안에서 즉시 모달을 열지 않는다. 연출 완료 이벤트/다음 안전 tick에
   예약하여 위젯 파괴·재진입 충돌을 피한다.
3) 안내창은 Roll ID당 한 번만 생성한다. 같은 결과에서 접기/펼치기, Hover, 재배치,
   프레임 갱신 때문에 반복 표시되지 않는다.
4) 모달을 띄우기 직전 대상 row와 화면 생존 여부를 다시 확인한다.
5) 안내창이 열린 동안 재추첨, 확정, 하단 결정 등 뒤쪽 입력은 막는다.
6) AI 처리에서는 안내창을 띄우지 않는다. AI도 같은 결과/상태 규칙만 조용히 적용한다.

[빈 개성칸이 있는 경우의 안내]
`꽝입니다. 재추첨할 수 있습니다. 이 결과를 확정하면 개성칸 하나가 X로 소모되며,
다음 논공 추첨에 열정 버프가 적용됩니다.`

[이미 9/9인 경우의 안내]
`꽝입니다. 재추첨할 수 있습니다. 이 결과를 확정해도 기존 개성은 지워지지 않으며,
이번 보상은 꽝으로 끝납니다. 다음 논공 추첨에는 열정 버프가 적용됩니다.`

안내창은 설명만 한다. 닫기 동작 자체가 꽝 확정, 재추첨 또는 하단 결정을 대신하면 안 된다.

===============================================================================
7. 6단계 평가·근거 화면·로그 처리
===============================================================================

1) 꽝은 실제 개성이 아니므로 6단계 평가 대상에서 완전히 제외한다.
2) 꽝에 `평범`, `무난`, `의외`, `대박`, `파격`, `충격` 중 어떤 등급도 붙이지 않는다.
3) 계산 근거 화면에는 필요할 때 `꽝 — 평가 없음` 정도의 결과 사실만 표시하고,
   개성 적합도·희소성·특수성 점수는 계산하지 않는다.
4) 로그에는 최소한 아래를 서로 구분해 남긴다.
   - outcome=miss
   - result_trait=null
   - miss_previewed
   - miss_rerolled_or_cancelled
   - miss_committed
   - x_slot_index 또는 full_9_no_x_slot
   - passion_granted / passion_active / passion_consumed
5) 꽝을 기존 개성의 ID 0, 잘못된 ID, 빈 문자열 결과처럼 기록하지 않는다.
6) 꽝 안내창 때문에 원작 감사/복귀가 추가 호출되면 안 된다. 기존 R2의 하단 결정 후
   원작 연출 1회 및 정상 복귀 흐름만 유지한다.

===============================================================================
8. 저장·로드·재추첨 규칙
===============================================================================

1) 무장별 잔여 재추첨권, 최종 반영된 X 마스크와 열정 버프 상태를 기존 sidecar
   저장 저널/스키마에 증분 필드로 보존한다. 별도 새 저장 시스템을 만들지 않는다.
2) 꽝 미리보기 또는 별도 확정만 해 둔 미완료 transaction은 기존 규칙대로 저장을 막는다.
3) 원래 하단 결정이 성공한 뒤에만 X와 열정 버프를 원자적으로 함께 commit한다.
4) 로드 후 이미 확정된 꽝 결과, X, 열정 버프를 다시 추첨하거나 중복 부여하지 않는다.
5) 구버전 저장에는 X와 열정 버프가 없는 기본값을 사용한다. 과거 결과를 소급 변경하지 않는다.
6) 저장/로드 반복을 막는 별도 안티 세이브스컴 기능은 추가하지 않는다.
7) 아직 추첨하지 않은 상태로 저장한 뒤 로드하여 새로 추첨하면 RNG에 따라 다른 결과가
   나올 수 있다. 이는 허용한다.
8) 이미 추첨·최종 반영된 결과는 기존 R2 규칙대로 로드 때문에 달라지지 않는다.
9) 저장·로드 후에도 각 무장의 잔여 재추첨권이 서로 섞이지 않아야 한다.
10) 구버전 상태에 무장별 잔여 횟수가 없지만 무장별 재추첨 이력을 복원할 수 있다면
    `5 - 해당 무장의 사용 횟수`로 복원한다. 복원 근거가 없다면 그 무장만 5개로
    초기화하며, 하나의 전역 잔여값을 모든 무장에게 복사하지 않는다.

10. 필수 회귀검사
===============================================================================

[꽝 발생 및 확정]
- 꽝이 낮은 확률 분기로 실제 발생한다.
- 세 번째/마지막 기회에서는 꽝이 절대로 발생하지 않는다.
- 꽝을 재추첨하거나 취소하면 X와 열정 버프가 생기지 않는다.
- 꽝을 선택하고 하단 결정까지 완료했을 때만 둘이 함께 적용된다.
- transaction 실패 시 X만 생기거나 열정 버프만 생기는 반쪽 commit이 없다.

[무장별 재추첨권]
- 새 대상 무장은 각자 재추첨권 5개로 시작한다.
- 한 무장의 세 보상칸에서 사용한 횟수만 그 무장의 5개에서 차감된다.
- 같은 페이지의 다른 무장과 다른 페이지의 무장 잔여 횟수는 변하지 않는다.
- 페이지 전환, 정렬, 스크롤, row 재생성 뒤에도 무장 ID별 잔여 횟수가 맞다.
- 무장 A에서 일부 사용한 뒤 무장 B로 이동하면 B는 자기 잔여 횟수를 표시한다.
- 다시 무장 A로 돌아오면 A의 이전 잔여 횟수가 그대로 표시된다.
- 플레이어와 AI가 서로의 재추첨권을 소비하지 않는다.
- 저장·로드 후에도 모든 무장의 잔여 횟수가 개별적으로 복원된다.

[X 점유칸]
- 빈 칸이 있을 때 X가 한 칸을 점유하고 이 패치의 수용량 계산에도 포함된다.
- X가 실제 개성 효과, 중복/상충, 교사 비교, 후보 가중치에 들어가지 않는다.
- 모든 개성 표시 화면에서 같은 무장의 X가 보인다.
- X Hover가 잘못된 실제 개성 설명을 띄우지 않는다.
- 다른 무장으로 이동하거나 화면을 닫은 뒤 stale X가 남지 않는다.
- 외부 편집으로 실제 개성이 들어오면 실제 개성을 보존하고 해당 X만 정리한다.
- 9/9 무장의 꽝이 기존 개성을 삭제·교체·가림 처리하지 않는다.

[열정 버프]
- 꽝을 최종 확정한 그 무장에게만 부여된다.
- 다른 무장, 다른 세력, 플레이어/AI 상태가 섞이지 않는다.
- 다음 기회에서 꽝 확률 0과 좋은 후보 가중 보정이 적용된다.
- 같은 기회에서 재추첨해도 유지되고, 실제 개성을 최종 반영할 때만 소모된다.
- 화면 취소, 저장/로드, 재실행 뒤에도 필요한 경우 유지된다.
- 열기와 열정 상태가 로그 및 저장에서 구분된다.

[UI·수명]
- 약 1.2초 연출 종료 뒤 안내창이 Roll ID당 한 번만 뜬다.
- 안내창 중 뒤쪽 입력이 실행되지 않는다.
- row 파괴, 화면 닫기, 재진입 순간에 모달/X 위젯으로 인한 충돌이 없다.
- 공용 X 리소스를 중복 해제하거나 파괴하지 않는다.
- AI에서는 팝업이 뜨지 않는다.

[평가·저장·기존 기능]
- 꽝에는 6단계 평가가 생성되지 않는다.
- 로그의 outcome=miss와 result_trait=null이 분리되어 있다.
- 구버전 저장은 기본값으로 정상 로드된다.
- 확정된 꽝/X/열정은 로드 후 중복 적용 또는 재추첨되지 않는다.
- 미추첨 상태의 저장/로드 후 새 결과가 달라질 수 있으며 이를 막지 않는다.
- R2의 기존 DB 원본 능력치 규칙과 실제 편집·성장 능력치 보존 검사가 그대로 통과한다.
- 기존 DLL assertion 245개와 패키지 정적 assertion 99개를 포함한 현재 gate를 유지한다.

11. 완료 기준 및 인계 규칙
===============================================================================

1) 위 기능은 실게임 Windows CE 한국어판에서 직접 확인하기 전까지 실게임 검증 완료라고
   표시하지 않는다.
2) 실제 확인 항목은 X 리소스/위치, 모든 개성 화면 표시, 모달 입력 차단, 저장/로드,
   9/9 처리, 버튼/row 수명, 원작 대사·복귀 1회다.

   HANDOFF_MANIFEST.json만 정상 절차에 따라 갱신한다.
4) 사용자에게 INI, 주소, 명령어를 직접 수정하라고 요구하지 않고 기존 INSTALL.cmd 진입을 유지한다.
5) 중단 시에는 기존 R2 전체를 새로 설명하는 문서가 아니라, 현재 소스·DLL·변경 diff·검사 결과와
   이 추가 수정지시서를 함께 압축해 넘긴다.

12. 한 줄 요약
===============================================================================

RC4 R2는 그대로 두고, 재추첨권은 가챠 대상 무장마다 5개씩 독립 관리한다. 낮은 확률의
꽝을 별도 결과로 추가하고, 꽝을 실제로 확정한 경우에만 빈 개성칸을 X로 점유하며 해당
무장에게 다음 논공 기회의 열정 버프를 준다. 마지막 칸에는 꽝이 없고, 9/9 무장은 기존
개성을 건드리지 않은 채 보상만 꽝으로 끝낸다. X는 모든 개성 화면에 보이지만 실제
개성·효과·6단계 평가에는 존재하지 않는 것으로 처리한다.
