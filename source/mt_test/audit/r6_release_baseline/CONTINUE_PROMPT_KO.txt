최신 사용자 규칙 — R5 문서보다 우선
- 지휘병사 증가만 개성 해금으로 대체. 선택 방식·내정 보상은 원작 그대로.
- 두 줄 합계는 현재 원작 한도(최대3). 각 줄은 왼쪽부터.
  이미 아랫줄2인 조운은 윗줄 첫칸 OR 아랫줄 셋째 중 하나만 추가한다.
- 무장별/기회별 결과·선택·교체 상태를 분리하되 한도는 두 줄이 공유한다.
  '숙련/노련/중진 고정 세로열별 독립 2택1'이라는 다른 규칙을 만들지 않는다.
- 추첨 성공 시 원작 선택 등록. 결과칸은 내정과 같은 선택 색상.
  다시 누르면 원작처럼 선택 해제/재선택, 결과 재생성 없음.
- 확정은 하단 결정만. 상단 확정·나감 객체 없음.
- 뒤로/ESC: 예·아니오 경고. 예=미확정 결과/임시 선택 초기화 후 원작 취소.
  이미 사용한 개인 재추첨권은 복구 안 함. 논공 비용/랭크/개성/X/열정 미적용.
  아니오=현재 결과와 개인권 유지. 이미 확정된 보상은 유지.
- 1명당 총5개, 모든 장수 공용 금지. 성공한 재추첨 즉시 예약 차감.
- 실제 교체는 결정 뒤 무장·기존·새 개성 예/아니오 확인. 모두 예일 때만 원작 확정.
- '계산 근거' 중앙, 선택 글꼴. 재추첨은 선택과 높이/위치/폰트 통일.

이번에 확정한 원작 코드 근거 (중요)
analysis/native_reward_layers.json 및 r6_range_8a2c50.asm:
F_STATUS=0은 해금됐지만 비활성. 1은 선택 가능(선택 여부는 별도 원작 카운트),
2는 이미 획득, 3은 랭크 잠금. R5의 '0=선택 가능' 해석이 잘못됐습니다.
상태1 타일에 원작 입력을 연결하지 않아 결정이 비활성이던 문제도 함께 수정.
원작 0x770080은 upper/lower prefix를 std::map node+0x20 low/high nibble로 관리.
row 렌더러는 별도 2바이트 upper/lower와 CCmnButton vslot0x208로 선택색 표시.
원작 getter call 0x8a2f87 e8348ee3ff → 0x6dbdc0.
원작 refresh call 0x770236 e8d5150100 → 0x781810.
새 SelectionConfig는 기존 Resolver 뒤에 추가. R6 기능DLL/개인Resolver를 함께 배포.
시작 시 두 callsite/target 검증. 공통 Loader/Core/기본Resolver/Hover는 수정 안 함.
F_CLOSE 0x6be850은 inner+0x178/17c가 바쁘면 종료 거부. 미확정 원작 선택을
복구하고 원래 refresh를 호출한 뒤 원래 취소 입력을 한 번 보냄.
알 수 없는 busy 필드를 강제로 0으로 쓰지 않습니다.
