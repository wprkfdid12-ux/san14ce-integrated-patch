가장 최근 R4에서 이어 완료한 부분
- 중요: 제공된 Core의 hook 등록 함수는 게임 이미지 주소만 받습니다. R3는 Hover DLL 내부6개
  호출도 Core에 넘겨 실제 초기화가 거절될 수 있었습니다. 이전 모의 Patch 접점의 범위 검사 누락도 수정.
  R4는 검증된 DLL 내부 호출만 소유 모듈 전용 transaction으로, 게임 정보창1개는 원래 Core로 등록.
  Core 파일/범위 제한은 수정하지 않습니다. 실제 Core 등록 기계코드로 거절과 수정 후 성공을 확인.
  모든 대상·원래bytes·겹침을 먼저 확인하고 보호 변경 후 재확인. 캐시/보호 복구 실패 때 relay 보존.
- X가 있는 정보창에서 실제 붉은 개성이 숨겨지던 문제 수정. 표시용 조회와 가챠 후보 필터 분리.
  실제 이름/색은 native DB 그대로, 가챠 후보는 기존 파랑/황금만. 능력치/실제 개성 덮어쓰기 없음.
- SAN14_MeritSlotDisplayV1은 초기화 전/미로딩/잘못된 보조정보/잘못된 ID에서 안전하게0 반환.
  반환 실패 때 출력0, 상대 패치는 원래 표시로 fallback. UI thread에서만 호출하는 SDK 헤더 제공.
- 제공된 정확한 출진 프리셋 RC25 전용9칸에 X 연결. DLL 파일을 교체하지 않는 optional runtime bridge.
  전체 text 해시+게임포인터+설치상태+13개 원래call 확인. 원래 refresh 다음 X만 그립니다.
  실제 개성명/색/툴팁ID/입력/프리셋 데이터 그대로. X는 가짜 개성ID나 tooltip ID를 받지 않습니다.
- Core 모듈 로딩 순서 대응: 초기화 + 성공한 새 게임/로드 경계에서 연결 재시도. 프레임별 탐색 없음.
- 다른 RC25 버전/변조/할당 실패는 해당 연결만 거부. 논공과 공통 Hover는 그대로 유지.
  일부 기록 실패는 소유bytes만 rollback; 보호변경 실패 때 살아 있는 relay 메모리는 해제하지 않음.
- 실제 RC25 refresh 기계코드의9칸 표시 루프까지 대체 native접점으로 실행해 X/붉은 개성/외부 편집 검사.
- gacha.c,h / runtime_flow / native_ui / native_controls / observation / event_log / slot_store /
  resolver / 공식DB는 R3와 해시 동일. 확률·장수별5권·먹통수정·저장v3 규칙을 바꾸지 않았습니다.
- 추가 실행 검사82개. 기존329개와 패키지 검사까지 모두 다시 실행해 총411/135 통과.

최종 능력치 규칙 — 이전 편집 능력치 반영 요청보다 우선
공식 대상과 교사 모두 DB 원본 능력치 분포를 비교합니다. 조광 ID619 = 65/68/53/51/60.
편집·성장한 실제 게임 능력치는 절대 되돌리지 않습니다. 비교 입력만 원본을 씁니다.
제안서의 앞4축을 유사도에 쓰고 근거에는5축을 표시합니다. 합계 기준이 아닙니다.
원본 DB 없는 신무장만 현재 기본값 fallback. 현재 개성·고유전법·부모는 live 유지.

R3에서 완료한 코드

- 세 번째 물리 보상칸, 시간순 마지막 기회, 열정 적용 기회는 꽝0%.
- 별도 확정 후 원래 하단 결정이 성공해야 X와 열정이 함께 반영됩니다.

- 수용량은 실제 개성+X. 효과·상충·교사·6단계 평가에서는 X/꽝을 제외합니다.
- 실제9/9는 기존 개성 유지, 결과만 꽝, 열정 부여. 외부 실제 개성이 X 자리를 채우면 X만 제거.
- 열정은 무장별, 다음 시간순 기회에 적용. 적합도>=0.5 가중치1.35배, 황금1.5배.
  재추첨·취소·저장/로드 동안 유지, 실제 개성 최종 반영 때만 소모. 기존 열기와 별개.
- 각 무장마다 평생3기회에서 개인 재추첨권 총5개. 페이지/장수 사이 공용 아님.
  정상 취소로 사용한 재추첨권을 돌려주지 않음. 세이브스컴 방지 기능은 추가하지 않음.
- 꽝 안내는 연출1200ms 완료 다음 안전tick에 기존 native 위젯으로 생성. 닫기는 설명 확인뿐.
- 나감/ESC는 원작 취소 버튼 이벤트를 호출. 화면 fade만으로 상태를 남기던 경로 수정.
  재추첨 여부 무관. 모달/결과 뒤에서 대기한 하단 결정 요청은 버려 자동commit 방지.
- 가챠 결과는 기존 Hover 엔진에 정확한 실제 개성 ID 전달. 별도 설명 DB 없음.
  비활성 버튼의 부모가 hit target일 때도 연결. 연출·다른 모달 뒤의 설명은 차단.
- 정확한 기존 Hover 코드 해시에 한해7개 display bridge 추가. Hover DLL 파일 자체는 동일.
- 저장v3: GSlot64/GState232 크기는 그대로, 과거 padding 사용. 기존 두 세대 저널 유지.
  v2는 새 필드0으로 이관하되 디스크 원본bytes/결과/저널 body hash를 바꾸지 않음.
- MISS 로그 result_trait/evaluation/fit 등은 null. 미리보기·버림·commit·열정 부여/소모 구분.

   검증하지 못했습니다. 적절한 원작 X 리소스가 없다고 단정하지 마세요. 아이콘 재사용은 미완료.

중요한 다운그레이드 제한
R2는 R3의v3 보조 저장을 읽지 못합니다. 설치 전 세이브백업.cmd로 원본+보조정보를 함께 백업.
R4는 R3와 저장 구조/알고리즘이 동일하며 새로운 저장 이관을 추가하지 않았습니다.
R3에서 저장 후 R2로 되돌리려면 패치 롤백만 하지 말고, 대응하는 설치 전 백업도 함께 복원해야 함.
보조정보를 지워 맞추거나 결과를 새로 뽑는 우회 금지. 모호한 저장 이력은 기존 fail-closed 유지.
