R13 실제 변경내역 — R12-UIFastPath에서 계속 작업

1. 미확정 앞 칸 리롤
기존 Preview의 ACCEPTED는 뒤 칸 추첨을 위해 잠시 적용한 계산 상태였으나,
리롤 허용과 클릭 처리가 이를 최종 확정처럼 다뤘다. 실제 저장 상태의 확정 여부와 분리.
세 칸을 연 뒤에도 원하는 칸을 선택하고 한 칸만 재추첨한다.
원본 장수/보상 상태와 이미 소비한 리롤 원장에서 순서대로 계산 상태를 재구성한다.
나머지 결과·시드·roll ID·당시 확률 및 해당 칸의 리롤 횟수는 유지한다.
뒤 칸과 중복/상충하거나 물리 슬롯·교체·꽝 상태가 성립하지 않는 후보는 추첨 전에 제외.
일반 최초 추첨·AI의 분포/배율은 변경하지 않았지만, 앞 칸을 편집하는 경우에는
고정해 둔 뒤 결과와 양립하는 후보로 조건부 추첨한다. 전체를 몰래 다시 뽑지 않는다.
리롤 총5회, 취소 시 미환급, 최종 결정/기존 교체 동의, 확정된 칸 잠금 유지.

2. 공통 UI 처리 성능
R12 report()는 공유 Core.log를 통해 UI 진단마다 CreateFileW/WriteFile/CloseHandle을
게임 호출 경로에서 실행했다. 활성화 이후 진단은 기존 유한 로그 큐/스레드로 보낸다.
스레드가 없거나 큐가 차도 동기 파일쓰기로 되돌아가지 않는다. 진단만 드롭하고 게임 판정은 유지.
초기 모듈 설치 전 메시지는 기존 Core 로깅을 사용할 수 있다. Core DLL 자체 수정 없음.

논공 확정 전/후 sync_all_merit_history 전체 순회를 실제 배치 대상만 검사하는 것으로 변경.
새 군주의 첫 AI 확정에서도 해당 군주 자격과 사용 이력을 먼저 확인한다.
새 게임·로드·저장에는 기존 전체 정합성 검사를 유지한다.

한 콜백에서 이미 검증한 장수 레코드에 대해 같은 메모리 가독성 검사를 반복하지 않는다.
다른 프레임으로 포인터/메모리권한을 캐시하거나 미검증 레코드 접근을 허용하지 않는다.
X가 없는 장수 표시에는 불필요한 실제 무장 테이블 조회를 하지 않는다.
X가 있으면 원작 현재 개성을 읽어 외부 편집과 중복되지 않게 하는 기존 처리를 유지한다.

3. 보존/배포
R11 유비/마등 정상 처리, 원작 종료, 후크39곳, 공유/지원 DLL5개, 설치기 본문 보존.
R12 대비 payload 변경은 메인 DLL, 버전 INI, 설명 JSON 세 파일.
정확한 R12 해시를 업그레이드 허용 목록에 추가. 저장 v3 형식 그대로.
현재 빌드 로그에 R13을 표시하도록 수정하고, 구 R10 문자열을 기대하던 검사도
새 버전 문자열을 정확하게 기대하도록 갱신했다. 원작 판정 검사를 생략하지 않았다.

실제 FPS 관측 및 자동 검사 범위는 검증결과.md 참조.
