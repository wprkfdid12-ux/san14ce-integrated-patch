# R13 미확정 칸 리롤 · 공통 UI 처리 개선 검증

**RC4-R13-PreviewReroll_Perf / 2026-09-21. Windows 전체 게임에서 R13의 FPS는 아직 직접 측정하지 않았습니다.**

## 기준과 영상

이번 작업은 배포한 R12-UIFastPath 소스/DLL에서 이어 진행했습니다. R12 DLL SHA256은
`1de57229e56cfe01485bfd0bcf7e3dff691742f9d7bac1a32639b3d390e2a83d`입니다.
사용자는 R11에서 유비 논공과 마등 승급 무충돌을 확인했고, R12에서도 여러 화면의 지연을 제보했습니다.

`11(7).mp4`에서는 세 개 결과가 열린 뒤 앞 칸을 선택하는 동작을 확인했습니다.
이 영상에서 읽을 수 있는 게임 FPS 숫자를 얻었다고 주장하지 않습니다.
`22(4).mp4`에서는 다음 **화면상의 게임 FPS 표시**를 직접 읽었습니다.

| 영상 시점(약) | 화면 | 표시 FPS |
|---|---|---:|
| 0초 | 논공 화면 | 60 |
| 1초 | 장수 선택 목록 | 39 |
| 6초 | 감사 대사·일러스트 | 18 |
| 9초 | 지도/명령 인터페이스 복귀 | 5 |
| 10초 | 지도/명령 인터페이스 | 11 |

두 파일은 30fps로 인코딩된 녹화입니다. 인코딩 프레임률과 게임 표시 FPS는 별개입니다.
이는 선택한 프레임의 관측값이지 전체 구간 평균/최저/클릭 지연의 정밀 측정값이 아닙니다.
여러 UI에서 하락하는 예시로 다뤘으며, 영상 속 창에만 적용되는 연출 단축 패치를 하지 않았습니다.
원본에서 자른 확인용 프레임과 관측 기록은 Source의 `audit/video_r13`에 있습니다.

## 1. 앞 칸 리롤

R12는 뒤 칸 계산에 필요해 임시 적용한 Preview의 ACCEPTED 상태를 리롤 제한에도 사용했습니다.
또 원작 선택 처리로 앞 칸을 다시 누르면 뒤 선택을 해제할 수 있었습니다.
R13은 실제 저장 상태의 최종 확정과 계산용 임시 상태를 분리합니다.

3칸을 연 뒤 어느 칸이든 선택하여 그 칸만 리롤합니다. 나머지 칸의 결과·시드·roll ID·해당 칸 리롤 횟수·당시 추첨 메타데이터는 보존합니다.
원래 장수 상태와 소비 원장으로부터 임시 개성/예산/열기/X 상태를 다시 구성합니다.
뒤 칸과 중복·상충하거나 물리 슬롯/교체/꽝 제약을 만족하지 못하는 후보는 난수 호출 전에 제외합니다.
따라서 이미 고정한 뒤 결과를 유지하는 **조건부 후보군**이며, 이 경우까지 기존과 모든 후보 확률이 똑같다고 주장하지 않습니다.
일반 첫 추첨과 AI의 분포 함수·배율·일반/황금/DLC 자료는 바꾸지 않았습니다.

원작 하단 결정과 필요한 기존 개성 교체 동의를 거쳐야 실제 지급합니다. 취소는 미확정 결과를 버리되 소비한 리롤을 돌려주지 않습니다.
개인별 총 5회, 최종 확정된 칸 잠금, 선택 합계 3회, 기존 저장 형식 v3는 유지합니다.

실제 DLL + 원작 클릭·자격·랭크·확정 코드 시험:
- 유비 3칸 공개 → 1·2·3·1·2번 리롤, 나머지 결과/선택 보존, 6회째 거절.
- 원작 확정 비용 1회, 종료 1회, 3개 결과 및 리롤 5회 원장의 저장·로드 바이트 일치.
- 앞 칸 꽝↔개성 전환, 임시 X 재구성, 취소 후 리롤 미환급, 진짜 저장정보 오류 거절.
- 만석 장수의 임시 교체 및 최종 동의, 다른 장수의 세 결과/쿠폰과 독립.
- 12개 결정적 시드 조합에서 각각 5회 혼합 순서 리롤과 최종 상태 검증.

## 2. 공통 처리 비용

### 게임 호출 경로의 동기 진단 로그

기존 공유 Core의 실제 `0x10a0` 로그 함수를 분석·실행했습니다. 이 함수는 메시지마다
CreateFileW → WriteFile → CloseHandle을 호출합니다. R12의 UI 생성/행 해제 진단이 이 경로를 사용했습니다.
R13은 활성화 이후의 진단을 기존 유한 큐/로그 스레드로 보냅니다. 큐가 차거나 스레드가 없어도
게임 스레드의 동기 파일 쓰기로 되돌아가지 않습니다. 진단 누락은 게임 자격/지급을 승인하지 않습니다.
공유 Core 파일과 저장정보의 필수 동기 쓰기는 바꾸지 않았습니다.

### 전체 이력 순회와 화면 조회

논공 확정마다 전체 유효 장수 이력을 전·후 두 번 검사하던 처리를 실제 배치 참여 장수로 제한했습니다.
AI 첫 호출에서도 새 군주를 대상별로 즉시 확인하며, 저장/불러오기/새 게임은 전체 정합성 검사를 유지합니다.
공통 후보/랭크 함수 내부에서 이미 검증한 같은 장수에 대한 가독성 검사를 재사용합니다.
X가 없는 장수의 표시 경로에서는 불필요한 무장 테이블 재조회를 생략합니다.
X가 있으면 현재 게임의 실제 개성을 확인하는 기존 외부 편집 대응은 유지합니다.
검증을 통째로 끄거나 다른 프레임까지 포인터/메모리 권한을 캐시하는 방식이 아닙니다.

### 같은 입력의 실제 DLL 비교

| 시험 부하 | 계수 | R12 | R13 |
|---|---|---:|---:|
| 장수 1,000명 중 1명 논공 확정 | 무장 테이블 조회 | 2,003 | 4 |
| 같은 확정 | 메모리 가독성 검사 | 10,023 | 22 |
| X 없는 1,000명 × 9칸 확인 | 무장 테이블 조회 | 9,000 | 0 |
| 같은 표시 확인 | 메모리 가독성 검사 | 36,000 | 9,000 |
| 후보 자격 1,000회 | 메모리 가독성 검사 | 7,950 | 3,000 |
| AI 후보 1,000회 | 메모리 가독성 검사 | 6,050 | 2,050 |
| 현재/예정 랭크 각각 1,000회 | 메모리 가독성 검사 | 2,050 | 1,050 |
| 동일 UI 생성 + 20개 행 해제 | 게임 경로 로그 파일 열기/쓰기/닫기 각각 | 61 | 0 |

마지막 행은 실제 배포 Core 코드와 두 실제 모듈 DLL을 실행하고 Win32 파일 서비스만 시험용으로 대체해 계수했습니다.
R13에서는 동일한 61개 기록을 메모리 큐로 보냈습니다. 128개 큐 포화/스레드 부재 시에도 게임 경로 파일 호출은 0이었습니다.
다른 비교에서도 동일 자격/랭크 반환값, 무관한 장수·상태 바이트 불변을 확인했습니다.

**이 숫자는 내부 호출 횟수입니다. 실게임 FPS나 성능 배수, 디스크 지연 시간의 측정값이 아닙니다.**
영상의 모든 프레임 저하가 이 코드만으로 발생했는지, 다른 모드/GPU/원작/운영체제 원인이 함께 있는지는 분리하지 못했습니다.

## 빌드·회귀·설치 보호

최종 **10개 시험군, 917개 단언 검사 통과**. 현재 결과는 `audit/r13_suite_run.json`입니다. 최종 DLL 지문, 각 시험 종료값, 건수를 함께 기록합니다.
R6/R7/R9 선택·취소·통지·레이아웃 수명, 저장/저널/변조, X/9칸/호버/프리셋, 스택, R11 유비/마등·AI,
R12 새 군주 즉시 인식/캐시 수명, R13 리롤/작업량 비교와 패키지 검사를 실행합니다.
구 테스트의 R10 로그 버전 기대값은 R13으로 갱신했지만 오류 기록 검사는 유지했습니다.

R12 대비 설치 payload 변경은 메인 DLL·버전 INI·설명 JSON 세 파일입니다.
전용 Resolver/Core/공유 Resolver/Hover/dxgi 지원 DLL 5개 및 기존 39개 후크 위치는 그대로입니다.
설치·원복·백업·진단 스크립트는 배포 R12와 바이트가 같은지 검사합니다.
R12와 R11/R10/R9의 정확한 업그레이드 지문을 인식하며 알 수 없는 파일을 강제 교체하지 않습니다.

검사는 Linux에서 실제 Win64 DLL 및 원작 명령어 일부를 호출하되 OS·게임 세계·UI 위젯 등의 경계를 대체합니다.
실제 Windows의 설치기 실행, Steam·GPU·장시간 플레이 시험이 아닙니다.
`ReleaseReady=true`는 설치 허용 표식이지 실게임 품질 인증이 아니며 `LiveGameTested=false`를 유지합니다.

## 남은 확인 범위

R13을 사용자의 같은 세이브로 실행했을 때 여러 UI의 실제 FPS/클릭 반응이 회복하는지는 아직 확인하지 못했습니다.
60FPS 보장, 모든 모드 조합/컨트롤러/장기 진행/모든 저장 손상 복구를 선언하지 않습니다.
원작 종료·감사 대사·연출 시간·게임 FPS 설정은 보존했으며, 이번 수정 때문에 새 게임이나 보조 파일 삭제가 필요하지 않습니다.
