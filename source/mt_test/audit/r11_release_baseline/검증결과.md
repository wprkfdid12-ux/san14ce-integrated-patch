# R11 검증결과

**RC4-R11-NativeFlow / 2026-09-21. 실게임 실행 인증은 아직 하지 않았습니다.**

## 근거와 방법
첨부 R10 설치본과 이전 채팅에서 회수한 R10 소스의 payload DLL 해시가 일치함을 확인했습니다.
R9 요청서 NEXT-001~005를 수정 기준으로 삼았습니다. 사용자에게서 제공된 한국어판 EXE와 2026-09-20의
런타임 코드 기록을 결합해 원작 함수를 분석했습니다. 이 기록은 현재 마등 멈춤 시점의 크래시 덤프가 아닙니다.
전체 게임 EXE나 런타임 텍스트는 이 배포본에 포함하지 않습니다.

시험은 **이번 소스에서 빌드한 실제 Win64 DLL**을 Microsoft x64 호출 규약 브리지로 실행합니다.
핵심 원작 함수 일부도 수집한 실제 명령어를 실행합니다. 게임 세계 데이터, 운영체제, UI 위젯,
전환 관리자·비용 서비스 일부는 시험용 대체 경계입니다. Windows 프로세스·GPU·사운드·Steam 실행 시험이 아닙니다.
원본 필터가 거부하는지/후크가 통과시키는지를 나눠 검사하며, 리스트에 미리 무장을 넣어놓는 것만으로
'실제 목록 노출 검증 완료'라고 판단하지 않습니다.

## 직접 확인한 결함과 교정

| 항목 | R10 또는 R9 결함 | R11 교정 및 시험 |
|---|---|---|
| 성공 후 멈춤 | R10이 정상 성공을 차단하고 실패할 수 있는 취소 디스패처를 성공으로 간주 | 비활성 취소 버튼 조건에서도 원작 성공 큐 종료 1회, 취소 호출 0회 |
| 중복 화면 종료 | R9가 성공 상태를 0으로 바꿔 원작 페이드 완료가 또 종료를 전송할 수 있음 | 성공 상태 1 유지. 원본 페이드 콜백·늦은 종료·반복 tick에도 1회 |
| 군주 제외 | 원작 후보와 확정 공통 필터 1eed10은 여전히 군주 거부 | 변경 전 거절/변경 후 통과를 실제 명령어로 비교. 멤버 필터의 군주 허용도 확인 |
| 군주 랭크/선택 | 3fa90/3fae0에서 군주 랭크 0, 원작 선택 합계와 표시가 맞지 않음 | 현재/예정 조회·실제 자료 기반 3회 용량·원본 행 상태 함수를 함께 검사 |
| 유비 확정 | 시험에서만 자격/선택 한도를 맞추는 것으로는 원작 확정이 검증되지 않음 | 유비 ID 952로 원작 1ebca0 및 1ebc60을 실행, 3결과/중진/정상 명령 비용 1회 확인 |
| 마등 종료 | 실제 보고는 마등 논공 후 정지 | 마등 ID 771로 개성/내정 성공 경로, 비활성 Cancel, 원작 페이드/중복 이벤트 시험. 실게임 재현은 별도 |
| 신분 변화 | 윗줄만 검증 완화하면 이미 쓴 내정·선택 총량을 잃을 수 있음 | 마등의 윗줄1+내정2와 군주 이력 복원, 동일 상태 저장/불러오기, 변조 거절 |
| AI 조회 부작용 | 후보 방문만으로 기존 윗줄 보상을 자동 추첨 | 100/200회 방문에서 추첨·보상 0회. 실제 확정에서만 추첨 |
| AI 9칸 | 원래 교체 경로가 남을 수 있음 | 9/9: RNG 0·교체 0·내정. 8/9: 개성1+내정2. 스타/군주도 동일 |
| 빈 결정/내부 통지 | 정상 선택과 빈 batch/화면 갱신 이벤트를 구분해야 함 | 빈 원작 확정은 비용/RNG/추가 종료 0. 내부 행 갱신 통지는 미리보기 0 |
| DLC/콜라보 | R9 후보 누락, R10에서 보강됨 | R10의 39개 개성/44개 문서화된 교사 유지, 실제 분포 가중치 검사 |

## 회귀 및 재현 가능성
최종 통과 목록과 소요 시간/시험 DLL 해시는 Source ZIP의 `audit/r11_suite_run.json`에 기록합니다.
핵심 추가 시험은 `tests/test_r11.py`, 원본 명령어와 대체 경계 설명은 `tests/r11_fixture.py` 및
`analysis/r11_native_boundaries.json`에 있습니다. `audit/R10_to_R11_NativeFlow.diff`는 실제 변경 차이입니다.

기존 R6 선택/취소, R7 알림·입력, R9 선택 소유자·해제, 개성 엔진/저장/마우스 설명/RC25 표시 및 스택 검사를 재실행합니다.
이전 시험 중 '후보 방문 때 자동 지급해야 한다'와 '저장된 지급 이력이 있어도 현재 윗줄 값이 0이면 무조건 거절'은
이번 요구와 반대이므로 R11의 새 검증으로 대체했습니다. 그 변경은 `test_r11_semantics.py`에 명시합니다.
성공을 취소로 우회해야 한다는 R10 종료 단언 역시 새 원작 성공 경로 시험으로 대체합니다.
오래된 audit 문서는 보관 자료이며 현재 버전의 완료 근거가 아닙니다.

## 설치 검증
8개 payload 해시, Win64 PE 형식, 실행/쓰기 동시 섹션 부재, 초기화 export, 동일 소스 재빌드 결과,
공유 DLL 바이트 보존, R9/첨부 R10 업그레이드 해시, 스크립트 인코딩·기본 구조·백업/롤백 보호를 검사합니다.
PowerShell 설치기를 실제 Windows에서 실행한 결과는 아닙니다. `ReleaseReady=true`는 설치기 실행 허용 표식이지
실게임 품질 인증이 아닙니다. `LiveGameTested=false`를 별도로 기록합니다.

## 아직 확인되지 않은 범위
실제 사용자의 시나리오·세이브·현재 멈춤 덤프는 제공되지 않았습니다. 정확히 같은 마등 멈춤의 직접 재현 및 해결,
유비가 현재 세이브의 목록에 실제 보이는 화면, 정상 턴·남은 명령서·금·다른 행동 실행은 실게임 확인이 필요합니다.
다른 장소/임무/행동 완료 등 원작 자격 제한은 유지하므로 '군주 무조건 상시 표시'가 아닙니다.

R11이 관찰하거나 R9/R10 보조 파일에 남은 군주 이력은 유지합니다. 이미 기록 없이 소실된 군주/내정 이력은
추측해 만들어내지 않습니다. 이전에 발생한 임의의 저장 차단을 모두 복구하는 만능 세이브 수리 패치도 아닙니다.
계정/슬롯/세이브 짝 불일치나 진짜 손상 검사는 그대로입니다.

장기 진행·모든 신분 전환·컨트롤러 입력·빠른 입력·UI 해상도·다른 모드 조합·60FPS·실제 감사 대사 출력은
여기서 완전 인증하지 않았습니다. 입력 통지 방어를 보강했지만 알려지지 않은 이벤트 순서를 전부 해결했다고 주장하지 않습니다.
