이미 세이브에 확정된 개성은 정리하거나 삭제하지 않습니다. 원작의 초기 배치와 편집 허용 조합이 다를 수 있으므로 신규 획득 제한을 적용합니다.
사용자 개성은 기존 Resolver 범위인 ID 355 미만의 실제 보유 개성을 검사하며, 사용자 제작 개성을 새로운 추첨 출처로 추가하지 않습니다.

## 원작 규칙 근거

[코에이 CE 한국어 매뉴얼](https://www.gamecity.ne.jp/manual/sangokushi14-pk/ce/kor/5300.html)은 개성의 조건부 발동을 설명합니다. 전체 상충표가 공개된 웹 문서라는 뜻은 아닙니다.
세부 규칙은 첨부 감사, 원본 추출 219개 개성 DB, 확보된 CE 실행 코드의 편집 판정을 대조했습니다. 현재 무장 성별은 편집 객체 +0x4A와 다른 실제 무장 객체 +0xA9입니다. 해당 접근자와 개성 판정 코드의 지문을 초기화 전에 확인합니다.
추가 반대 효과 11쌍은 이름만으로 무조건 차단하지 않고 원작 분기의 연결 무장 유효성까지 읽습니다. 소스의 `analysis/r16_trait_native.json`에 지문을 기록했습니다. 보관 중인 실행파일 사본 일부가 잘려 있어, 이번 기록은 온전한 코드 구간과 이전 전체 디스어셈블을 근거로 했으며 전체 EXE 무결성 재검증이라고 표시하지 않았습니다.

## 연계무장 표시 패치

- 확보본: RC2.4 HoverPin, RC2.4 ProxyCompat1, RC2.5 HoverPin SafeLoader.
- 공통 ModCore와 기본 Resolver의 해시가 동일합니다. 연계 기능 DLL은 수정하거나 함께 재설치하지 않습니다.
- 논공 Resolver의 실제 39개 훅, 9칸 확장·선택·정보창 경로와 연계 패치의 6개 훅 및 양쪽의 코드 검사 범위에 충돌이 없습니다.
- 연계 패치는 기존에 확장된 개성 열을 복사한 뒤 별도 열을 덧붙입니다. 논공은 해당 연계 열을 다시 쓰지 않습니다.
- 기존 dxgi.dll이 확인된 공통 로더이면 그대로 사용합니다. 확인된 version.dll / dinput8.dll 로더도 재사용합니다. 새 로더가 필요하면 비어 있는 경로 하나에만 설치합니다.
- 문자열이 비슷한 임의 DLL은 호환으로 간주하지 않습니다. 미확인 프록시가 세 자리를 모두 점유하면 안전하게 중단합니다.

PowerShell 7.4.6/Linux에서 실제 설치 스크립트를 임시 폴더에 실행했습니다. 설치·재설치·제거·직전 복원·R15 업그레이드·부분 복사 실패 복구 등을 검사했습니다. Windows DLL 로딩 API만 시험 대역으로 바꿨으며, 배포 스크립트에는 Windows에서 기능 DLL 2개와 로더 후보 3개의 실제 로딩/진입점 검사를 유지했습니다.

## AI 처리 측정

같은 시험 환경의 100명·군주 10명·5개 고정 난수 입력 묶음입니다. OS·부대/화면 경계는 대역으로 처리했습니다.

| 지표 | R15 | R16 |
|---|---:|---:|
| 논공 AI 콜백 중앙값 | 46.74 ms | 26.81 ms |
| 첫 묶음 전체 확률 계산 | 400회 | 300회 |
| 첫 묶음 재사용 | 135회 | 137회 |
| 첫 묶음 실제 재추첨 | 149회 | 149회 |

1명만 처리하는 소규모 묶음도 별도로 측정했습니다. 중앙값은 R15 0.428ms, R16 0.273ms입니다. 최초 점검에서 발견된 반복 메모리 검사 비용을 보정한 최종 DLL의 결과입니다. 게임이 소유한 개성 객체의 수명은 세계 로드/재시작 시 초기화하고, 매번 현재 필드를 읽으면서 새 객체 주소만 다시 검사합니다.

매 묶음 300개 상단 보상을 완료하고 무장별 총 5회 제한, 원래 개성 보존, 저장 상태 유효성을 검사했습니다. 성별·상충 제한으로 후보가 달라지므로 R15와 모든 추첨 결과가 같다는 주장은 하지 않습니다. 후보 존재 검사 최적화는 같은 R16 전체 확률 계산과 1,088명 전원에서 일치합니다.
이 수치는 **실제 게임 FPS나 영웅집결 전체 AI 턴 시간**이 아닙니다. 왼쪽 메인 인터페이스 프레임 드랍, 마제 시나리오 세이브, 연계 화면의 동시 렌더링은 실게임에서 추가 확인이 필요합니다.

## 사용자 요구 및 제보 상태

- 재추첨권: 윗줄 개성 가챠 3칸만 적용. 아랫줄 내정은 사용·차감 0. AI 재추첨 유지.
- 군주 하단 보상: R15에서 수정한 현재 군주 시정 보상과 기존 영토 상한을 유지. 기존 군주별·하단 보상·세이브 회귀 시험 통과.
- 일반 무장 ‘숙련’ 시작/공적 4,000 제보: 공적·다음 단계 해금 조건은 유지. 해금 때만 선택하고 확정 후에는 임의로 재개방하지 않음.
- 장비 원본 제보: 게임 장면·세이브가 없어 같은 현상의 재현이나 유일한 원인 확정은 하지 않음. 통제 시험에서 중복 획득 방지와 실제 배열 기반 표시 보정 확인.

## 재현 방법과 자료

소스 ZIP에서 `source/build.sh --main-only`로 재빌드하고 `tests/run_r16.py --with-package`로 검사합니다. `MERIT_ZIG`에 Zig 실행파일 경로를 지정합니다. 설치 시험은 `tests/test_r16_installer.ps1`, AI 측정은 `tests/bench_r16_ai.py`에 있습니다.
`audit/r16_*`가 이번 결과입니다. `audit/r15_*` 및 이전 버전 스크립트는 과거 근거이며 R16 합격 기록으로 재사용하지 않습니다. 전체 실행은 `audit/r16_suite_run.json`과 각 로그로 확인합니다.
