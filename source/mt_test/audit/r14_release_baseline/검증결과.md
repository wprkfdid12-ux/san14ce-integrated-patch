# R14 왼쪽 명령 메뉴 조회 개선 검증

**2026-09-21 / RC4-R14-MainMenuQueryPerf. R14의 실제 게임 FPS 회복은 아직 직접 측정하지 않았습니다.**

## 관찰과 원인 판단

첨부한 미설치 영상의 선택 프레임에서는 게임 FPS가 59~60, 설치 영상에서는 처음 60에서 왼쪽 명령 메뉴가 나타나는 구간에 44, 이어 43으로 떨어졌습니다. 녹화 자체는 모두 30fps입니다. 카메라 위치와 경로가 달라 평균 프레임률을 일대일로 비교한 시험은 아닙니다.

게임의 정확한 실행 코드에서 `CMainCmdLayout` → 명령 갱신 → 논공 후보 필터 → 패치의 후보·관직 조회로 연결되는 경로를 확인했습니다. R13의 이 조회는 장수마다 Core.readable을 호출하고, 공유 Core는 Windows VirtualQuery로 메모리 구역을 확인합니다. 군주 조회에서는 이미 고정된 게임 이미지 주소도 반복 검사했습니다.

따라서 **메뉴 갱신 때 누적되는 반복 메모리 확인이 가장 유력한 병목**입니다. 정적 호출 관계와 불필요한 호출 자체는 확인했습니다. 실제 사용자 PC에서 이것이 추가된 프레임 시간의 몇 ms를 차지하는지, 다른 병목도 있는지는 아직 계측하지 않았습니다. Hover DLL의 공용 경로도 조사했으나 이번 영상의 직접 원인이라고 입증하지 못해 해당 DLL은 보존했습니다.

## 실제 수정

- 정확한 원작 함수 지문과 준비된 월드를 확인한 네 장수 조회 콜백에서, 원작과 같은 CPersonData 객체 수명·타입 계약을 이용합니다. 매 호출마다 Windows 메모리 조회를 반복하지 않습니다. 원작의 F_VALID 판정은 유지합니다.
- 이미 계산한 중진 관직은 현재 DB 주소가 같은지 직접 확인해 반환합니다. DB 변경, 저장 불러오기, 새 게임, 테이블 갱신 시 다시 확인합니다.
- 외부 표시 API, 초기화, 저장·로드, 신규 군주의 실제 세력 소유권 검사는 유지합니다. 후보 결과를 시간으로 캐시하지 않아 같은 틱의 군주 승계를 지연시키지 않습니다.
- 읽기용 호출량 export와 `UI호출진단.cmd`를 추가했습니다. 게임 안에서 타이머·파일 출력·추가 전역 훅을 실행하지 않습니다. 도구는 외부에서 0.25초마다 128바이트 카운터를 읽습니다.

## R13 실제 DLL과 비교

무장 1,000명 중 기록된 군주 50명, 월드 준비 후 동일한 입력을 사용했습니다. 실제 Win64 DLL과 원작 판정 코드 일부를 실행했고, Windows/게임 서비스 접점은 모의 구현입니다.

| 1,000회 조회 | R13 Core.readable 호출 | R14 | 결과 |
|---|---:|---:|---|
| 논공 후보 | 3,000 | 0 | 동일 |
| AI 후보 | 2,050 | 0 | 동일 |
| 현재 관직 | 1,050 | 0 | 동일 |
| 예정 관직 | 1,050 | 0 | 동일 |

이는 **반복 조회 경로의 호출 횟수**입니다. 1회 메뉴 전환에 반드시 1,000명씩 검사한다는 뜻이나, 게임 FPS가 일정 비율로 오른다는 뜻은 아닙니다. 초기화·로드·신규 군주·할당/위치 객체의 검사가 필요한 경로에는 메모리 검사가 남아 있습니다.

원본 R13 메인 DLL SHA256: `4c88b9de8ce71b10c40632b01eb44b30c38d2b218165668ca28250c3dadb88e9`.

## 검증 범위

최종 시험은 11개 묶음, 총 876개 검사 항목을 통과했습니다. 회귀 결과와 검사 수는 Source의 `audit/r14_suite_run.json` 및 `audit/r14_package_tests.json`에 기록했습니다. 승계 즉시 반영, 군주·일반 무장 자격, 누적 포상 이력, 리롤, 결정·취소·페이드, 저장 복원, 지문 불일치와 부분 설치 롤백을 검사합니다. 패키지 검사에서는 원본 R13 업그레이드 인식, 실제 배포 DLL 해시, 메인 DLL 재빌드 일치, Win64 형식, 공유 파일 보존을 확인합니다.

Windows의 전체 게임/GPU, 사용자 세이브로 실행하는 설치기, 새 PowerShell 진단 도구의 실제 실행은 이 Linux 환경에서 확인하지 못했습니다. PowerShell은 정적 검사만 시행합니다. DLL 조회 시험을 실게임 FPS 회복 인증으로 표현하지 않습니다.

## 적용 후 확인

게임을 종료하고 INSTALL.cmd로 R13 위에 설치한 뒤, 같은 세이브·카메라·줌 단계에서 왼쪽 메뉴 표시/숨김을 비교하세요. 드랍이 남으면 `UI호출진단.cmd`로 30초간 같은 동작을 수집해 생성 ZIP과 영상을 함께 확인합니다. 진단은 FPS가 아니라 호출량이며, 카운터 필드 전체가 하나의 원자적 스냅샷은 아닙니다.

Source 증거: `analysis/r14_command_menu_path.json`, `audit/video_r14/observations.json`, `audit/r14_query_benchmark_r13.json`, `audit/r14_query_benchmark_r14.json`.

메모리 조회 API의 기능 참고: [Microsoft VirtualQuery 문서](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualquery). 이 문서의 내용으로 실제 게임 호출 비용을 추정하지는 않았습니다.
