# RC4-R5-SafeExit 검증 결과

## 작업 기준과 결론

이 대화에서 이어 온 R4 최종본을 증분 수정했다. 다른 채팅방 R5 소스는 병합하지 않았다.
사용자 영상과 로그는 그쪽 버전의 문제 사례이며, 우리 수정본의 실게임 재현으로 취급하지 않는다.

현재 production DLL 실행 assertion 564개, 패키지/빌드 정적 assertion 150개 통과.
R5 기본97개와 예/아니오 경고55개를 포함한다. 실제 C 엔진3,000회 순차 검사도 통과.
Windows 실게임·PowerShell 실행·DirectX 렌더링·실제 음향·FPS는 검증하지 않았다.
자동 검사는 사용자 환경에서의 튕김 해소나 모든 모드 호환을 보장하지 않는다.

## 점검 및 수정한 경로

- 무장별 pending, 개인권, stage별 교체 대상을 분리. 조통 결과 뒤 조광의 실제 해금 callback 검사.
- 개인 재추첨권 성공 즉시 예약 차감. 정상 뒤로 확정과 강제 detach 후 저장로드 모두 환불 없음.
- 뒤로/ESC는 먼저 원작 모양의 예/아니오 경고. 예만 마지막 결과를 준비해 원작 결정을 한 번 실행.
  아니오는 결과/개인권 유지, 경고 안의 새 ESC도 아니오. 원작 결정은 일반 확정 버튼으로 유지.
- 추첨 전 승계 선택은 정상 취소. 실패한 원작 결정은 같은 결과/권수를 보존하고 무한 반복하지 않음.
- 원작 F_STATUS가 받는 안쪽 무장 목록과 바깥 화면을 구별. 중첩 fixture로 잘못된 인수 탐지.
- unregister 전에 callback 무효화. row 갱신/소멸 전 연출 참조 복원, 재진입 차단,
  원작 자원 문맥 보존 및 소유 위젯 한 번 해제.
- 상단 확정/나감 객체 없음. 계산 근거 단일 문구, 중앙 정렬, 네이티브 폰트/높이 적용 검사.
  실제 해상도별 화면 배치는 사용자 환경 확인이 필요하다.
- 최신 규칙에 맞는 꽝 안내. 기존 Hover 및 R4의 Core/RC25 표시 연결 회귀 검사 유지.
- 로그에 SafeExit 빌드명 및 종료 단계 기록 추가. 이전 event mod가 R3로 남던 혼동 제거.

## 실행 범위

tests/run_r5.py --with-package가 현재 gate다.
test_rc4, cp03, stack_probe, native_integration, r1_skip, r2, r3, r4, r5, r5_warning, package 모두 exit0.
Win64 PE production 기계코드를 Microsoft ABI bridge로 실행한다.
R5는 캡처된 원작 state tick 기계코드도 실행하지만 OS/위젯/비용/대사 접점을 대체한다.
특히 메모리 할당기·실제 위젯 destructor·게임 입력 전체를 실게임에서 실행한 검사는 아니다.

R5 검사에는 다음이 포함된다.

- 조통ID649/조광ID619 동시 표시, 개인권 1개/5개 사용, 왕복 선택, 마지막 결과 각각 반영.
- Back/ESC × 첫 연출/결과/재추첨 연출/결과/꽝 안내, 한 번의 반환과 늦은 callback 무효화.
- toolbar 소유 행 소멸, 행 재활용, unregister 중 callback/refresh 재진입.
- 추첨 전 취소 무비용, 원작 결정 실패/재시도, 같은 장수 역순 기회 처리.
- 강제 detach 시 권수 보존/저장로드, 참고 영상과 비슷한 입력 순서 및 지연된 행 해제.
- 상단 버튼 부재, 계산 문구/정렬 및 모의 native Selection 폰트/높이의 정확한 일치.
- 예/아니오 경고의 원작 스킨/폰트, 본문의 native 대비 팔레트, 연출 일시정지/복귀,
  누르고 있던 입력, 버퍼 ESC, 숨은 결정/선택, 이전 경고의 Yes callback 거부,
  빠른 연속 응답, 부분 생성 실패/재시도 및 경고 중 소멸에 의한 임의 확정 차단.

test_r2/r3의 accept_preview는 내부 거래 경계 검사 helper다. 실제 상단 확정 버튼을 되살린 것이 아니다.

## 보존 확인

가챠 엔진 gacha.c/h, slot_store.inc, merit_resolver.c, 공식 무장DB와
display_patch/hover_x_adapter/presets_x_adapter/merit_display_api는 R4와 해시 동일.
확률·평가·저장v3·원본DB 비교 규칙을 다시 만들지 않았다.
Loader/Core/기본Resolver/Hover 파일도 기존 바이트 그대로다. 설치 대상은 기존 8개만이다.
다른 채팅방 R5는 전체 payload 해시를 검증한 뒤 논공 전용 파일의 정확한 이전 해시만 인정한다.
그 소스/DLL을 우리 구현에 혼합하지 않는다. 임의 파일 충돌은 계속 안전하게 거부한다.

DLL SHA256:
- SAN14_MeritTraits.dll: 24d1eb6d35e68e280ad93421fc89b0945b71921c2bc8e038d14d0df56435c989
- SAN14_MeritResolver_CEKO.dll: c77445b31f8dbf0b56bc63c4bd89c480e8ae586caa67d99326e6a087fc380cda

동일 도구로 재빌드한 해시와 실행 검사 DLL, 설치 payload DLL이 일치한다.
PowerShell은 BOM/CRLF, 구문 경계, 대상 allowlist·트랜잭션/백업·충돌 보호 등을 정적 검사했다.
실제 Windows PowerShell 설치 실행은 하지 않았다.

## 엔진 시뮬레이션

audit/safeexit_simulation.json: 공식1,000명 × 순서대로3회 =3,000회, 고정 seed.
꽝81/열정 적용81, 황금9, 파격3, 초월1. 실제 C 엔진을 Linux로 컴파일해 실행했다.
이는 초기 파라미터의 한 가지 순차 샘플이며 최종 밸런스/실게임 FPS 인증이 아니다.
기본 꽝5%와 마지막/열정 기회 제외 규칙 때문에 전체3,000회 비율은5%와 같을 필요가 없다.

## 남은 실게임 확인과 명시적 한계

실게임확인.txt의 조통·조광→재추첨→뒤로→지도 조작→재입장부터 확인해야 한다.
다른 채팅방 영상은 종료 직후 게임 화면 소멸을 보여주지만 제공 로그에는 충돌 주소/스택이 없다.
그 영상으로 우리 수정본의 같은 충돌을 입증하거나 해소 완료를 주장하지 않는다.

강제 world/layout 해제는 정상 뒤로가 아니다. 소멸 중 unsafe commit을 하지 않으며 권수만 보존한다.
스타9칸의 교체 미선택은 기존 획득 포기 규칙으로 기존 개성을 보존한다.
원작 X 아이콘 리소스 재사용은 미완료이며 현재 원작 글자 렌더러의 X를 쓴다.
정확한 제공 Hover/RC25 외 독립 커스텀 패널까지 자동 연동된 것은 아니다.
실제 저장/Steam 환경·화면 배치·Hover·음향·모드 조합의 확인이 필요하다.
