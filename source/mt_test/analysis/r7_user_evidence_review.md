# R7 증거와 수정 범위

최신 로컬 로그 `events.0.jsonl`은 `RC4-R6-NativeChoice`, session2170711023105974810을 기록한다.
원본은 사용자 첨부 ZIP에서 읽었으며 개인정보/원본 게임 로그는 패키지에 재배포하지 않는다.
사진은 조운 수전/교체 상승, 조통 불굴 선택 상태다. 영상은 별도 결과의 시도이며 동일 로그 세션으로 단정하지 않는다.

로그에는 조운596 원래 개성 [88,67,161,4,166,62,153,177,204], 마지막 결과 수전68,
개인 리롤5회, 조통649 절약118에서 불굴33, 개인 리롤1회가 나온다.
`tests/test_r7.py`는 해당 실제 seed 순서를 사용하여 동일 결과/권수와 원작 선택(1,2)/(1,0)을 재현한다.

R6에서는 확인창이 활성 상태인 동안 원작 결정/뒤로 입력을 차단했다.
그런데 사진/영상에는 확인창 내용이 없고 배경 컨트롤만 비활성으로 보인다.
R6의 확인창 구현은 논공 안의 큰 CCmnButton caption에 여러 줄 설명을 넣었다.
제공 RC25 소스는 원작 버튼 caption이 여러 줄 안내에 적합하지 않음을 명시하고 별도의 글줄을 만든다.
이 관찰은 R7 창 구성을 바꾼 근거다. GPU 표시 실패의 정확한 원인이나 layer10/11 자체의 무효를 입증한 것은 아니다.

R7은 제공 원작 CSimpleBalloonLayout 생성·크기조정·배경 생성 방식을 따른다.
독립 root와 자식 예/아니오, 별도 글줄, 원작 좌표·레이어·등록/해제 경로를 사용한다.
구조상 visible 상태가 사라지면 잠금을 해제하고 어떤 보상/취소에도 자동 동의하지 않는다.
별도 등록 컨트롤은 원작 무장선택 동안 중단하고 종료 시 역순으로 정리한다.

원본 로그 마지막 UI_UNREGISTER_BEGIN만으로 정확한 크래시 위치를 확정할 수 없다.
R7은 UI_OWNED_DETACHED / UI_NATIVE_UNREGISTER_BEGIN / END를 나누어 기록한다.
실제 Windows 게임·GPU를 실행하지 못했으므로 자동 검사 통과와 실게임 정상 플레이는 구분한다.
